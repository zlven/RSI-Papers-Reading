# 精读：FunSearch —— Mathematical Discoveries from Program Search with Large Language Models

> 论文：Romera-Paredes, Barekatain, Novikov et al. (DeepMind). "Mathematical discoveries from program search with large language models". Nature 2024（2023 年 12 月发布）。
> 阅读方式：单独精读。所有判断只基于本文自身文本。

## 1. 研究背景与动机

论文的出发点：LLM 直接生成科学发现（证明、算法）不可靠——幻觉、浅尝辄止、无法系统探索。但科学发现的许多对象可以表示为**程序**，而程序有一个巨大优势：**好坏可以自动执行验证**。动机由此清晰：把 LLM 从"一次性生成答案"的角色，改造成进化循环中的**变异算子**——它负责有创造力地改写程序，评估器负责无情地筛选，循环负责系统性探索。论文要证明：这个组合能在真实数学问题上产生超越人类已知的结果。

## 2. 核心 Insight 与理论依据

**核心 insight**："程序空间搜索"把 LLM 的创造力与自动验证的可靠性接合——
- 要求 LLM 只改写一个**语义集中的关键函数**（如装箱的 priority(score, item, bins)），而非整个求解器——变异单元小、语义明确，LLM 的改写质量高；
- **评估器充当不可贿赂的裁判**：程序必须真实运行出更好的结果才能存活，幻觉无法通过评估器；
- 进化的种群机制（岛屿模型）维持多样性，避免单链爬山陷入局部最优。

**理论依据**：遗传编程（genetic programming）传统 + LLM 作为语义感知变异算子的新组合。无形式理论；其方法论主张是：评估器驱动的循环把"发现"从生成问题转化为搜索问题，从而绕过 LLM 单次生成的不可靠性。

## 3. 方法详解

### 3.1 流程

1. 人工提供：问题骨架程序（含可调用的求解流程）+ 待演化的关键函数接口 + **自动评估器**；
2. 从程序数据库（种群，分岛屿）采样父代程序 + 历史高分样例，组装 prompt；
3. LLM 生成关键函数的新版本（变异）；
4. 程序执行 + 评估器打分；有效且高分者入种群；
5. 岛屿间周期性迁移，循环数万至数百万次评估。

### 3.2 可修改范围与 RSI 分级

| 可修改对象 | 是否被修改 | 修改者 |
|---|---|---|
| 关键函数（问题求解程序） | ✅ 逐代演化 | LLM（变异算子） |
| 骨架程序/评估器 | ❌ 人工提供固定 | —— |
| LLM 权重 | ❌ 冻结 | —— |
| 进化规则 | ❌ 固定 | —— |

**分级：L0**。改进的对象（程序）与改进者（LLM）完全分离；LLM 自身零变化。FunSearch 的价值恰在于以**最纯粹的形态**展示了一阶改进回路的力量：连模型都不更新，仅靠"创造力 + 严格评估 + 种群积累"就足以做出新科学发现——这为整个谱系标定了"什么不算 RSI 但仍极具威力"的基线。

## 4. 实验设计

- **问题**：cap set 问题（加性组合学的开放问题）；在线装箱（online bin packing）启发式。
- **验证方式**：cap set 构造的正确性由数学性质自动核验；装箱启发式在大规模实例集上与传统启发式（best-fit 等）对比。
- **消融/分析**：prompt 中历史程序的作用；岛屿模型的多样性贡献；程序规模/复杂度演化分析；与 LLM 直接生成（无进化循环）的对照。
- **同行评议**：Nature 发表，构造结果经数学界检验——评估的权威性在本谱系中最高。

## 5. 评估三问

### Q1：内部判据

**自动评估器（程序执行）**。全谱系判据强度第一档：候选程序必须在真实问题实例上跑出更好的分数才能存活。判据的代价是完全**问题专用**——每个新问题都需要人工编写评估器与骨架。这个"判据人工性"是 FunSearch 范式推广的主要摩擦点。

### Q2：外部审计

外部审计由问题的数学性质本身承担：cap set 构造可被独立验证，装箱启发式可在任意新实例上复测。论文的评估还包含一层"科学共同体审计"——新构造被数学家检查其新颖性与正确性。这是"held-out 基准"之上的更强外部性。

### Q3：量化方式

cap set 构造规模（维度 vs 集合大小的渐进行为）+ 装箱的实例级性能对比 + 消融曲线。归因到组件（prompt 历史/岛屿/函数接口设计）粒度。发现的"知识含量"由数学界定性评估。

## 6. 实验结果与分析

- **cap set**：发现了当时已知最大的 cap set 构造（在特定维度上超越历史最佳），是 LLM 参与的首批**新数学结果**之一；
- **在线装箱**：演化出的 priority 函数启发式在大规模评估上超越人工设计的经典启发式，且被实际采纳（论文报告其部署考量）；
- **消融**：去除进化循环（只用 LLM 单次/少量生成）无法达到同等结果——证明收益来自**搜索循环**而非模型单次能力；岛屿与历史回灌各自有贡献；
- **可解释性红利**：产出是可读程序，人类数学家能从中提取洞见（论文强调发现的程序帮助理解了问题结构）。

**分析**：FunSearch 最深远的结果不是某个构造本身，而是证明了一个分工原则——**让机器在它可靠的地方（执行、筛选）做机器的事，让 LLM 在它擅长的地方（有语义的局部创造）做 LLM 的事**——这个原则足以产出同行评议级别的科学发现。

## 7. 结论与意义

FunSearch 开创了"LLM × 进化 × 自动评估"的科学发现范式，直接启发了 AlphaEvolve 及后续一整条程序进化线。在 RSI 谱系中它是 L0 的定锚标本：改进完全外化于模型，却展示了评估器驱动的循环所能达到的高度——后续所有"真 RSI"工作都必须声称自己比这个基线多了什么（通常是：改进对象内化为模型/脚手架本身）。

## 8. 未来方向（论文自身展望）

论文展望：扩展到更多数学与科学问题；让系统自己发现"该演化哪个函数接口"；与符号推理工具更深结合。

## 9. 批判性问题清单

1. **人工脚手架的重度依赖**：骨架、函数接口、评估器全部人工——"自动发现"的前提是人工完成了问题形式化这一最难的部分。
2. **适用范围**：只有"解可程序化验证"的问题适用；证明类、理论类发现无法进入该框架。
3. **评估成本**：数万次程序执行的算力开销与问题的评估器速度强相关；慢评估器的问题不可行。
4. **LLM 贡献的定位**：变异算子换成其他生成机制（随机变异 + 大算力）能获得多少同等结果？论文消融部分回答了循环必要性，但 LLM 相对传统遗传编程变异算子的独立贡献界定仍可更细。
5. **发现的泛化性**：演化的启发式是为训练分布的实例优化的——分布外实例上的稳健性需要逐问题检验。
