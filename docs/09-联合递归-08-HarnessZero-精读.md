## 1. 动机漏斗：六步走到问题

1. **大目标**：通用 agent 的能力最大化。
2. **现状**：harness 能大幅提升 agent 性能，但**增益绑定在部署时的 harness 上**。
3. **裂缝**：最优 harness 随域、实例、模型而变（Multi-Harness RL 的 7.13pp 方差是同期独立证据）→ 通用 agent 陷入二难：忍受次优共享 harness，或维护路由到不断膨胀的专用 harness 集合。
4. **问题**：能否把专用 harness 的增益**转移进权重**，让单一固定 harness 下也能保住？
5. **约束**：两个 harness 的**动作空间和可用信息不同**——优化 harness 的轨迹不能直接当目标 harness 的监督信号（这是蒸馏的技术障碍，也是前人没做的原因）。
6. **本文问题**：设计跨动作空间的 harness 蒸馏机制。

**金句**（改写自 abstract）：蒸馏的目标不是复制 harness，而是让 harness 可以被拿走。

## 2. Insight 与理论依据

### 核心 Insight

把 harness 重新定位为**训练期的脚手架（scaffolding 原义）**：它的价值不在部署时的执行增益，而在它能诱导出模型原本不会展现的行为模式——这些模式可以被蒸馏内化。

这与 SKILL0 的技能内化同构（运行时组件 → 训练期课程 → 权重），但 Harness-Zero 多走一步：它蒸馏的不是内容（技能文本），而是**行为分布**（harness 诱导的 28 个行为模式，恢复率 82.3%）。

**蒸馏后超蒸馏源**（44.3% > 41.7%）的机制解释方向（摘要未给，推测）：专用 harness 的执行开销/约束在部署时造成损失，而内化行为无此开销——harness 是带损耗的行为诱导器，蒸馏是无损的行为载体。若全文证实，这是"harness 作为训练工具优于作为部署工具"的强证据。

## 3. 方法拆解（摘要可推断部分）

### 关键设计

**设计 1：agent-as-harness（核心机制）**
- 功能：在优化 harness 的指导下，一个 harnessing agent 在**目标 harness 的动作空间内**、执行前纠正 student 的响应，把 harness 指导转写成训练演示。
- 核心思路：动作空间不匹配 → 不用 code 做监督转换，用**一个 agent 做实时翻译/纠正**。发现 1（agent-as-harness > code-as-harness）说明这个翻译角色代码化做不好——跨动作空间对齐需要理解而非规则。
- 设计动机：解决 §1 约束 5。

**设计 2：蒸馏目标 = 部署解耦**
- 训练用专用 harness 的指导，评估时移除它。与 WHALE/Co-Harness 方向相反：它们让 harness 越来越好，Harness-Zero 让 harness 越来越不必要。

### 与 Gödel 谱系的关系

无递归、无自指——但它是 **L5 现实路径的关键组件技术**：若联合递归的权重侧更新依赖 harness 轨迹（WHALE/HELIX 都是），Harness-Zero 提供了"harness 差异 → 权重更新"的成熟管道，且自带动作空间对齐方案。HELIX 的 438 条学习记录要变成 M_{t+1}，大概率需要类似机制。

## 4. 实验声称（摘要数字，未核）

| 发现 | 数字 |
|---|---|
| 基模型 macro-average 成功率 | 23.3% |
| +专用 harness（部署时保留） | 41.7% |
| **Harness-Zero（部署时移除 harness）** | **44.3%** |
| 行为模式恢复率（3 域 28 模式） | 82.3% |
| agent-as-harness vs code-as-harness | 前者优（前沿 LLM + 同一进化 harness） |

域覆盖：知识工作、工具使用、科学。
**疑点**：23.3% 的基线起点偏低，44.3% 的绝对水平在 frontier 语境下不算高——蒸馏在小基线上的增益能否平移到大模型？"28 个行为模式"的标注方式（人工？自动？）决定 82.3% 的可信度。

## 5. 评估三问

**Q1 内部标准**：任务成功率 + 行为模式恢复率（双指标：结果 + 过程）。恢复率是**机制层面的评估**，比单看成功率严谨。
**Q2 外部审计**：蒸馏后评估在移除 harness 的固定目标 harness 下进行——评估条件诚实（没有在蒸馏源的 harness 下评）。seed/方差未知。
**Q3 量化**：三组对比（基线/带 harness/蒸馏后）构成天然归因链；成本未报。

## 6. Contribution 提炼

1. **提出 harness 蒸馏任务**：harness 从部署资产变为训练资产——12 篇中独有的问题定义。
2. **agent-as-harness 对齐机制**：跨动作空间监督转换的 agentic 解法，且证明优于 code 方案。
3. **蒸馏超源现象**（44.3 > 41.7）：若稳健，改写 harness 的成本收益分析。
4. **行为恢复率指标**：把蒸馏评估从结果层扩展到机制层。

## 7. 缺点与攻击面

1. **单向无递归**：蒸馏完就结束了——蒸馏出的模型配什么 harness 最优？（HELIX 的 Rebuild 问题在此重现）没有闭环。
2. **基线起点低**：23.3%→44.3% 的相对增益可能随基线升高而压缩。
3. **28 模式的枚举完备性**：恢复率分母由谁定？未观察到的模式不计入分母——82.3% 可能是幸存者偏差。
4. **harnessing agent 的成本与身份**：用什么模型当纠正者？若纠正者本身强于 student，增益里有多少是蒸馏了纠正者的能力而非 harness 的行为？（与 SIA 的混淆同款）

## 8. 谱系定位

**蒸馏模式双篇**：

| 维度 | Harness-Zero | SKILL0 |
|---|---|---|
| 蒸馏对象 | harness 诱导的行为分布 | 技能库内容 |
| 对齐问题 | 动作空间不匹配（agent-as-harness） | 上下文渐进撤回（Dynamic Curriculum） |
| 部署终态 | 固定目标 harness | 完全 zero-shot |
| 核心数字 | 44.3% > 41.7%（超源） | +9.7/+6.6/+10.1%，<0.5k token/步 |
| 开源 | 未知 | **是** |

**对你的研究**：Harness-Zero 是"联合递归如何落地"的**缺失拼图**——WHALE/HELIX 都需要把 harness 侧改进转成权重侧更新，但只有 Harness-Zero 专研这个转换接口并给出量化（82.3% 恢复率）。follow 价值高：把 agent-as-harness 接进 HELIX 的 Update 阶段，三个组件（HELIX 基板 + DGM 存档 + Harness-Zero 蒸馏）两个半开源。

## 9. 批判性问题清单

1. 蒸馏超源（44.3 > 41.7）在几个 seed 上成立？方差多大？
2. harnessing agent 用什么模型？换掉它（更强/更弱），蒸馏增益如何变？——区分"harness 行为的贡献"与"纠正者能力的贡献"。
3. 28 个行为模式怎么枚举的？未枚举模式的恢复率不可知。
4. 蒸馏后的模型换新 harness（非目标 harness）表现如何？——内化行为是通用的还是过拟合到目标 harness 的？
5. 与直接行为克隆（BC）专用 harness 的轨迹相比，agent-as-harness 的增量是多少？（code-as-harness 只是部分对照）
