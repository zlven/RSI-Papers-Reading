## 1. 研究背景与动机

**领域位置**：智能体后训练（post-training）。现有范式在两个极端之间二选一：

- **冻结 harness、训模型**：SWE-smith、AgentTuning 等——把脚手架当作固定的数据生成环境；
- **冻结模型、搜 harness**：ADAS、OPRO 等——把模型当作固定的执行器。

**核心洞察**（论文贡献第一条的核心陈述）：脚手架与模型**不是独立的，而是互相依赖的两个优化轴**。harness 的质量决定轨迹的质量，轨迹的质量决定训练后模型的能力，而更强的模型又能利用更丰富的 harness——三者构成复合（compounding）增益链条。

**痛点**：
1. 冻结 harness 的训练继承了脚手架的缺陷：脏轨迹（可避免的崩溃、错误的工具调用）直接进入训练集；
2. 冻结模型的 harness 搜索止步于推理时收益，无法沉淀为持久能力；
3. 单向优化无法产生复合效应。

**核心问题**：能否把 harness 变成**后训练系统的可学习部分**，而非模型外的静态脚手架？

## 2. 核心 Insight 与理论依据

### 2.1 关键洞察

1. **共进化飞轮**（论文公式化表述）：
   Better harness → better trajectories → stronger model → better harness → …
2. **失败归因先于修改**：HarnessCritic 把每条失败轨迹归因到**结构化的 harness 层原因**（提示歧义、工具 schema 错误、技能缺失、中间件失配），修改由此有的放矢，而非盲目扰动。
3. **harness 修复先行、权重内化随后**：先在推理时修好脚手架，再用干净轨迹做 SFT 把行为**内化**为模型能力——"each successful Harness revision can become persistent model capability"（Model Alignment Loop 的动机陈述）。
4. **验证门控的局部 diff**：harness 修改以局部 diff 形式提出，仅在"目标失败模式改善且 held-out 行为不回归"时被接受。

### 2.2 理论依据与方法论谱系

- **无新形式理论**；方法论是"交替优化"（alternating optimization）在 模型×harness 联合目标上的实例化。
- 谱系：AgentTuning/FireAct 式轨迹蒸馏 + GEPA/ExpeL 式反思式脚手架优化 + 课程学习（更强模型解锁更丰富 harness）。
- 与 STaR 的关系：Model Alignment Loop 本质上是"在改进后的 harness 下做 STaR 式自训练"。

### 2.3 与已有工作的联系（按论文自身定位）

- **vs ADAS / OPRO**：它们冻结模型；Co-Harness 双轴。
- **vs SWE-smith / AgentTuning**：它们冻结 harness；Co-Harness 双轴。
- 论文自称"**the first framework to co-evolve both**"（贡献陈述原文），把 2026 年涌现的 harness 优化与权重训练两条线合并为一个闭环。

## 3. 方法详解

### 3.1 整体框架：双循环交替

每轮 t，从 (θ_t, φ_t) 出发：

1. **轨迹收集**：当前模型在当前 harness 下跑任务集。
2. **Co-Harness Loop（固定 θ_t，改进 φ）**：
   - 失败轨迹送入 LLM 版 **HarnessCritic**；
   - Critic 将失败归因到结构化 harness 层原因（prompt 歧义 / 工具 schema 错 / 技能缺失 / middleware 失配）；
   - 提出局部 harness diff；
   - **接受判据**：验证 rollouts 显示目标失败模式改善且 held-out 行为不回归；
   - 产出进化后的 φ_t*。
3. **Model Alignment Loop（固定 φ_t*，改进 θ）**：
   - 在 φ_t* 下重新收集高质量轨迹集 D_t；
   - 用 D_t 微调得到 θ_{t+1}——把改进后的行为分布内化进权重。
4. 新模型进入下一轮，可能暴露**新的** harness 层瓶颈；φ_{t+1} ← φ_t*。

### 3.2 可修改范围（RSI 视角）

| 层级 | 本文触及？ | 说明 |
|---|---|---|
| 提示词 | ✅ | HarnessCritic 的 diff 目标之一 |
| 工具 schema | ✅ | 修复错误 schema |
| 技能库 | ✅ | 引入可复用技能 |
| 中间件 | ✅ | 行为调整 |
| 长期记忆 | ✅ | 必要时扩展 |
| **模型权重** | ✅ | SFT 内化轨迹分布——本文标志性维度 |
| 改进规则自身（Critic 提示/SFT 配方/接受门） | ❌ | 固定 |
| 结构性 harness 重设计 | ❌ | 论文明示："Structural Harness redesign remains a human responsibility" |

**定位**：**harness 全层 + 权重层**的联合修改；是"修改范围层级表"中首个同时打满这两行的代表。

### 3.3 RSI 实现程度

- **改进闭环**：存在且为**双层闭环**——harness 侧每轮被改，权重侧每轮被训，两侧的产物互为对方输入。
- **改进器自身会被改进吗**：HarnessCritic（harness 侧改进器）的提示与归因素描固定；SFT 配方固定。无递归深度。
- **分级判定**：**L5（权重+脚手架联合递归，规则固定）**。理由：修改范围同时覆盖权重与脚手架且闭环互相喂养，符合 L5 定义；但"如何改"的规则不可被系统自身改写，故非完全自指。这是 2026 年"共进化"浪潮（SIA、WHALE、VACE 等同期工作）中配方最简、陈述最清晰的代表。

## 4. 实验设计

### 4.1 任务与模型

- **基准**：AIME24、AIME25、HMMT25——工具集成数学推理，难度递增（HMMT25 最难）。
- **模型**：Qwen3-8B 与 Qwen3-32B 两个尺度。
- **轮数**：两轮完整共进化（Round 1 / Round 2）。

### 4.2 Baseline

- **Baseline**：初始模型 + 初始 harness；
- **Human-designed static Harness**：人工精调的固定 harness（关键对照——检验自动共进化是否超越人工天花板）。

### 4.3 主结果

（§Experiments，Table 6 / Figure 5）

| 阶段 | 平均准确率 | 相对增益 |
|---|---|---|
| Baseline | 58.5% | — |
| Round 1 | 73.5% | **+15.0 pp** |
| Round 2 | 78.9% | **+20.4 pp（累计）** |
| Human-designed Harness | — | R2 超出其 **+24.7 pp** |

**难度交互**：
- HMMT25（最难）：+20.1 pp（8B）、**+27.2 pp**（32B）——越难受益越大，印证"脚手架缺陷在复杂多步任务中更致命"；
- AIME24（基线已高）：增益最小。

### 4.4 自主性案例

一次 **200+ 小时自主运行**中，系统在无人工干预下：修复了系统崩溃、提升了推理效率、并**自主发现了 ensemble 策略**——作为"共进化循环能发现非平凡设计"的轶事证据。

### 4.5 消融与变体

原文报告了单环变体（仅 harness / 仅权重）与归因质量分析（所读部分的要点）：
- 仅 harness 环：推理时收益但不持久；
- 仅权重环：继承脏轨迹缺陷；
- 双环：复合增益。

## 5. 评估和测评依据（评估三问）

### Q1 内部判据：怎么判断"修改成立"？

- **harness 侧**：门控式——HarnessCritic 归因 + 验证 rollouts（目标失败模式改善 + held-out 不回归）双重判据；
- **权重侧**：隐式——SFT 不做显式接受判断，依赖轨迹质量由上游 harness 门控保证；
- **性质**：**门控式（harness）+ 继承式（权重）**的复合判据结构。

### Q2 外部审计：怎么判断系统确实在改进？

- **标准竞赛基准**（AIME/HMMT）作为最终指标；
- **人工 harness 对照**：+24.7 pp 的超越是"非自我陶醉"的关键外部证据；
- **双模型尺度**：8B/32B 一致性降低了偶然性；
- **局限**：评估与进化使用同源基准家族的竞赛题（论文未报告 OOD 迁移实验——所读部分）。

### Q3 量化方式：如何度量改动？

- **harness 改动**：以 diff + 归因类别（四类原因）编目——改动归因结构清晰；
- **权重改动**：隐式（SFT 数据分布变化），无逐样本编目；
- **增益分解**：Round 1 vs Round 2 的分解展示了复合效应的节奏；
- **成本**：200+ 小时自主运行被提及，但系统性成本核算（token/GPU 时）所读部分未报告。

**评估三问总评**：Q1 的"归因→定向修复→回归门"三段式是 harness 侧判据的完整形态；Q2 的"超人工 harness"对照极具说服力；Q3 的弱点在权重侧——内化过程是黑箱，无法回答"权重到底学到了 harness 的哪部分"。

## 6. 实验结果与分析

- **主结果**：两轮 +20.4 pp、超人工 harness +24.7 pp；最难基准受益最大。
- **尺度一致性**：8B 与 32B 同向提升，且 32B 在最难任务上增益更大——能力与脚手架互补。
- **自主发现的性质**：ensemble 策略的涌现说明搜索空间覆盖了"非局部修复"的设计；
- **失败模式（论文 Limitations 自列）**：
  1. 需要**有能力的 critic LLM**——弱 critic 归因错误会污染整个循环；
  2. 冷启动需要**最低量的失败轨迹**；
  3. 多轮 SFT 的**算力开销大**；
  4. 对需要**反事实控制流推理**的失败模式，归因准确率下降；
  5. **结构性 harness 重设计仍是人类职责**。

---

## 7. 结论与意义

- **结论**：harness 应被视为后训练系统的可学习组件；harness 与权重的交替共进化产生任何单侧优化都无法达到的复合自我改进。
- **领域意义**：
  - 在 RSI 分级体系中是 **L5 的清晰实例**——把"权重层"正式纳入自我改进闭环，衔接了"脚手架进化"（2025 主线）与"共进化"（2026 浪潮）；
  - HarnessCritic 的**结构化失败归因**为"改动从哪来"提供了比随机变异更高效的答案，与 DGM 的无定向变异形成方法论对照。
- **局限**：见 §6 失败模式 + §5 Q2/Q3 的缺口。

## 8. 未来方向（基于原文 Limitations/Future Work）

1. **Online Co-Harness**：rollout 期间实时归因，长程任务的 run 内 harness 适应；
2. **RL 版 harness 进化**：用奖励信号搜索替代 LLM critic，可能发现非显然配置；
3. **多智能体 Co-Harness**：智能体间 middleware 层成为关键优化目标；
4. （论文愿景）从周期性批处理走向"与模型共同演化的持续在线脚手架健康监控器"。

## 9. 批判性问题清单（精读者视角）

1. **Critic 能力的循环依赖**：改进质量上限 = critic 的归因能力；用一个比被改进模型更强的 critic，是否变相引入了"外部强模型"（与 Self-Harness 刻意回避的设定相反）？论文未做 critic 强度消融（所读部分）。
2. **竞赛数学的窄域性**：AIME/HMMT 是可自动判分的干净环境；在软件工程、网页操作等噪声大的域，"目标失败模式改善"的验证成本会爆炸——方法的可移植性未证。
3. **SFT 内化的黑箱性**：权重侧没有任何归因机制；"更好的轨迹"中哪些成分真正被内化、哪些被丢弃，完全不可见。
4. **两轮即报告**：共进化承诺的是飞轮，但实验止于 Round 2；第 3–5 轮是否饱和、振荡或退化（harness 与模型互相过拟合）是关键未答问题。
5. **200+ 小时自主运行的轶事性**：ensemble 发现令人印象深刻，但单例报告、无对照、无失败日志统计——更像演示而非证据。
