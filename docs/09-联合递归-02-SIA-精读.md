## 1. 动机（漏斗）

1. **领域现状**：两个互不往来的 silo——harness 更新派（DGM、Meta-Harness、Hyperagents，权重冻结）与 test-time training 派（TTRL、Discover 线，harness 冻结）。
2. **现有痛点**：(1) harness 派的修改集中于软件工程卫生（解析、重试、路由），"很少交付基模型在任何 prompt 下都产不出的领域推理"；(2) TTT 派的增益来自内部策略改变，但交付管线是人写的、不随任务结构适应。
3. **核心矛盾**：两个杠杆的变化空间不相交（外部基础设施 vs 内部参数），单独优化任一者都留下对方够不着的增益。
4. **本文目标**：给定任务规范与 verifier，一个系统能否不加人工干预地同时改进 scaffold 与权重？
5. **切入角度**：让读全轨迹的 Feedback-Agent 在每步动态选杠杆——选择本身由观测到的奖励动态驱动。
6. **核心 idea**：harness 更新让模型 agentic（塑造搜索与行动方式），权重更新建立"任何 prompt 或 scaffold 都无法灌输的领域直觉"。

**判断**：问题真实（两 silo 确实孤立），但本文的解法把最难点（**何时选哪个杠杆**）交给了一个冻结的 LLM 先验——这是把研究问题转嫁给了最强的未受控组件（见 §9）。

## 2. Insight 与理论依据

- **核心 insight**：两杠杆的变化空间正交——harness 改"如何搜索"，权重改"知道什么"。最佳质性证据：MAGIC 降噪任务中，**第一个权重检查点引入了 scaffold 循环从未产生的结构不变量**（np.clip + np.rint 把插值计数取整为非负整数——一个生物学上平凡正确、但所有 harness 版本都没提出的约束）。
- **理论依据**：无形式理论；杠杆分工的论证是经验+概念性的。
- **严格使用还是隐喻借用**：主要是架构性贡献；"coupled co-evolutionary Goodhart"（§8）是有洞察力的自陈分析，但停留在定性。
- **逻辑跳跃**：从"三域双杠杆都更优"到"两 silo 应当合并"之间隔着基线公平性问题（见 §7）。

## 3. 方法

### 3.1 系统骨架

三组件循环：
1. **Meta-Agent**（Claude Sonnet 4.6）：从任务规范 U 与参考实现 R 生成初始 scaffold A₁；
2. **Task-Specific Agent**（gpt-oss-120b）：在沙盒中执行，产出全轨迹 τ_g（每实例的 prompt/响应/工具调用/结果/提取答案）；
3. **Feedback-Agent**（Claude Sonnet 4.6）：读 A_g 源码 + 全轨迹 τ_g + 指标 E_g，产出改进报告与下一步——**软标签两动作**：harness 更新（重写 scaffold）或 weight 更新（选择一种 RL 算法训练 LoRA r=32）；直到步数预算耗尽。

### 3.2 关键设计（三段式）

> **Feedback-Agent 的杠杆与算法选择**
> - 功能：每步决定改 harness 还是改权重；选权重时再决定用哪种 RL 算法
> - 核心思路：条件于任务类型与奖励动态（论文给出定性决策表：密集奖励+稳定性约束→PPO/GAE；episode 末 verifier+廉价 rollout→GRPO；右偏奖励直方图→entropic advantage weighting；防能力退化→REINFORCE+KL；奖励稀疏到梯度为零→Best-of-N BC 冷启动；只能排序不能打分→DPO）
> - 设计动机：让"元决策"由轨迹证据驱动——**但选择规则本身是冻结的 Claude 先验，这是全系统最重的未受控变量**

> **全轨迹反馈（而非聚合指标）**
> - 功能：让 Feedback-Agent 诊断具体失败模式
> - 核心思路：τ_g 包含每实例完整执行日志，不只是汇总分
> - 设计动机：聚合统计无法区分"解析器 bug"与"领域知识缺失"——这正是杠杆选择需要的信息

> **Sample-task 正则化**
> - 功能：防初始 scaffold 过拟合单一实例
> - 核心思路：Meta-Agent 生成 scaffold 时条件于多样任务规范
> - 设计动机：承认 scaffold 生成的过拟合风险（但无消融）

### 3.3 【RSI 专项】可修改范围

- ☑ harness（prompt/工具路由/答案提取/重试逻辑）　☑ 权重（LoRA r=32，lr 4e-5）
- ☐ Feedback-Agent 自身　☐ 杠杆选择规则　☐ verifier　☐ 训练基础设施（Modal 管线固定）
- 载体：harness 为代码重写；权重为 H100 上的 LoRA-RL。

### 3.4 【RSI 专项】RSI 实现程度

**判级：L2 × 双杠杆**。改进器（Feedback-Agent）固定，选择规则固定，无档案库/种群。与 WHALE 的差异：WHALE 是外置优化器的调度科学（L0），SIA 的 Feedback-Agent 至少在叙事上是"系统的一部分"——但它用 Claude Sonnet 4.6 而 task agent 用 gpt-oss-120b，**改进者与被改进者是不同厂商的不同模型**，所谓"self-improving"的"self"在模型层面不成立（系统层面成立）。

## 4. 实验

- **Benchmark**：LawBench（191 类中文罪名分类，5332 训练/913 测试）；AlphaEvolve TriMul CUDA（H100 内核优化，分数=1500/运行时）；MAGIC scRNA-seq 降噪（mse_norm）。
- **基线结构**：Baseline（初代 scaffold 下的 gpt-oss-120b）、SIA-H（纯 harness 最佳）、SIA-W+H（双杠杆最佳）；另有 Codex（5.5）与 Claude Code（Opus 4.7）作为现成 agent 参照。
- **主结果**：
  - LawBench：0.135 → SIA-H 0.500 → SIA-W+H **0.701**（前 SOTA 0.450）；
  - TriMul：1.00× → SIA-H 1.14× → SIA-W+H **14.02×**（1,017μs vs 前 SOTA 1,161μs）；
  - 降噪：0.048 → SIA-H 0.241 → SIA-W+H **0.289**（前 SOTA 0.240）。
- **协议**：Feedback-Agent 先做 harness 迭代、停滞后切换权重（注意：这意味着杠杆顺序在报告实验中是**分段式**的，与 §5.1 宣称的"自由交错"存在张力）。

## 5. 评估三问

- **Q1 内部判据**：确定性 verifier（每任务一个）；杠杆接受无显式门控——Feedback-Agent 的判断即门控（LLM 判断在提案端与验收端合一）。
- **Q2 外部审计**：**这是本文最弱处**。① 改进者与基线不同构：SIA 的 meta/feedback 用 Claude Sonnet 4.6，而对比的"现成 agent"（Codex/Claude Code）是通用产品配置——Lilian Weng 指出的混杂批评成立：无法区分"双杠杆的收益"与"强模型重写 scaffold 的收益"；② 无种子方差；③ "前 SOTA"口径未给出复现条件；④ 权重相位的增益全部以"harness 停滞后"为起点，无法排除"harness 相位被刻意/无意压低"。
- **Q3 量化方式**：逐代轨迹编目有（改进报告 artifact）；成本核算**完全缺失**（H100 训练时数、Claude 调用量均未报告）。

**总评**：三域三杠杆的证据形态是"存在性演示"而非"受控比较"；质性证据（np.clip+np.rint 案例）比数字更有信息量。

## 6. Contribution 与结论

- 自陈贡献：单环双杠杆架构；三域超 SOTA；杠杆分工的机制分析（RQ2）。
- **我的判断**：①架构贡献成立但新颖性有限（与 Co-Harness/WHALE 同期同构）；②"超 SOTA"需打问号——TriMul 的 14.02× 依赖权重相位，而权重相位的训练管线（Modal RL）本身是人类基础设施，"自主"边界模糊；③**RQ2 的机制分析是全文最有价值的部分**——"权重到达了 scaffold 从未提出的结构不变量"是双杠杆必要性的最直接证据。

## 7. 缺点与攻击面

- 作者自陈（§8，质量很高）：**耦合 Goodhart**——两个优化器对同一 verifier 的联合不动点是"对彼此更新历史互盲的纳什均衡"，在 OOD scaffold 或新策略下脆弱；标准 Goodhart 分析假设单优化器，双杠杆产生耦合变体。
- **额外缺点**：
  1. 杠杆选择是冻结 LLM 先验，全文最关键决策未受控、未消融；
  2. 实验混杂（改进者与被改进者不同模型；基线为通用产品配置）；
  3. 报告的实验实际是分段的（harness→停滞→权重），与"自由交错"的架构主张不符；
  4. 成本核算缺失；
  5. RL 算法选择表标注"observed across broader experimentation... deferred to v2"——即正文三域之外的未报告实验影响了方法描述，可复现性受损。
- **最可能被攻击的点**：混杂批评（强 meta 模型 + 弱 task 模型 + 弱基线）；分段执行与交错主张的矛盾。

## 8. 谱系定位

- **前置**：Meta-Harness（harness 算子最近邻）；Discover 线（Yuksekgonul et al. 2026，权重更新目标直接复用）；Hyperagents（作者自认的最近并行工作——它让 meta 机制可改但不动权重）。
- **后续**：其 §8 的耦合 Goodhart 分析与 §9 的 meta-RL over selector 是后续工作的直接问题来源。
- **一句话定位**：两 silo 合并的早期存在性证明，价值在问题陈述与机制观察，不在数字。
- vs 对比：
  - **vs WHALE**：相同点=同攻双杠杆协调；关键差异=SIA 用 LLM 启发式选杠杆（灵活但不可复现），WHALE 用受控调度（可复现但 proposer 外置）；
  - **vs Co-Harness**：相同点=agent 参与的权重内化；关键差异=Co-Harness 有 200+ 小时连续运行，SIA 是分段演示；
  - **vs Hyperagents**：它把自指往 meta 层推（改"改进机制"），SIA 把杠杆往权重层推——两个正交的扩展方向。

| 维度 | 本文 | WHALE | Co-Harness | Hyperagents |
|---|---|---|---|---|
| 可修改范围 | harness+LoRA 权重 | harness+权重 | harness+权重（agent 在环） | harness+meta 机制 |
| RSI 分级 | L2 双杠杆 | L0 双杠杆 | L5 | L3-（meta 可改） |
| 杠杆协调 | LLM 启发式选择 | 固定/自适应调度 | 双循环交替 | N/A |
| 外部审计强度 | 弱（混杂） | 强 | 中 | 中 |
| 成本核算 | 缺失 | rollout 级 | 未系统报告 | 未系统报告 |

## 9. 批判性问题清单（供组会讨论）

1. （§5/6）报告的实验均为"harness 停滞后切权重"的分段轨迹——请给出一个真正自由交错的运行记录，并证明交错优于分段（WHALE 的受控研究表明交替>分段，你们的架构主张与此一致但无证据）。
2. （§6.2）若把 Meta-Agent/Feedback-Agent 换成与 task agent 同档的模型（gpt-oss-120b 自己），双杠杆增益还剩多少？"self-improving"在改进者是外部强模型时的语义边界在哪？
3. （§6.3.3）np.clip+np.rint 案例被引为"权重到达 scaffold 够不着处"的证据——但它是 GRPO 训练后模型**产出代码中的两行**，这究竟是"权重内化了结构不变量"还是"训练分布移动后采样到了基模型本就可产出的代码"？如何区分？
4. （§8）耦合 Goodhart 的不动点分析：你们声称双杠杆系统在训练 verifier 上"显得强"但对扰动脆弱——有无对训练好的 (harness, LoRA) 组合做交叉扰动实验（新 harness×旧权重、旧 harness×新权重）？
5. （§7.3）RL 算法选择决策表来自"未报告的更广泛实验"——选择规则的验证集是什么？是否存在"算法选择"本身的过拟合？
