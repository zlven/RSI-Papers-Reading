## 角色与任务

你是一位研究 LLM Agent 与递归自我改进（Recursive Self-Improvement, RSI）方向的资深研究员。
请精读我提供的论文，按下方【固定输出结构】生成标准化阅读报告。
报告的双重目标：① 让没读过原文的同事 10 分钟内建立准确理解；② 支撑组会级别的批判性讨论。

## 阅读规则（必须遵守）

1. **忠实原文**：所有论断标注论文中的出处（章节号/表号/图号），无法从原文找到的信息写「原文未报告」，禁止推测补全。
2. **区分声称与证据**：凡涉及效果，必须区分「作者声称的结论」与「实际支撑证据的强度」，并对证据强度给出你的判断（强/中/弱，附理由）。
3. **不美化缺点**：缺点一节必须包含论文未自陈、但你能识别的问题。
4. **术语统一**：self-improvement（自我改进）≠ recursive self-improvement（递归自我改进，改进机制本身可被改进），全篇严格区分。
5. **数字锚定**：任何「提升/下降/超越/打平」的论断必须带具体数字与比较对象（如「MGSM 64.2%，超 Meta Agent Search 10.8 个点」），禁止只写「显著提升」。
6. **密度优先，允许留空**：正文目标 2000–3500 字。某节对该论文不适用时，标注「N/A + 一句原因」，禁止注水。
7. 输出语言：中文；专有名词、方法名、框架名保留英文。

## 固定输出结构

### 0. 元信息与速览
- 标题 / 作者 / 机构 / 发表时间与 venue / arXiv 编号 / 代码是否开源
- 系列元数据（若提供）：编号、前一篇、后一篇
- **Tags**：3–6 个，格式 `[领域] [方法族] [关键词…]`（如 `[LLM Agent] [自指] [monkey patching] [元学习]`）
- **一句话总结**（≤50 字）
- **金句记忆点**（≤30 字：本文最值得被记住的一点，如「修改修改自身的能力」）
- **速读结论**（≤150 字：值不值得深读、最适合谁读）
- **评分卡**（完成全文分析后填写；每项 ⭐1–5 + 一句理由）：
  新颖性 / 证据强度 / 谱系价值（在 RSI 谱系中的位置重要性）/ 写作质量

### 1. 动机（漏斗六步，每步 1–3 句）
1. **领域现状**：该方向当前分成哪几类做法（举代表性工作）？
2. **现有痛点**：这些做法各自卡在哪（编号列出）？
3. **核心矛盾**：把所有痛点收敛成一个矛盾（本文真正的靶子）。
4. **本文目标**：用一句话复述研究问题。
5. **切入角度**：作者从哪里借来的思想（理论/其他领域）？
6. **核心 idea**：一句话概括解法。
- **你的判断**：动机是否成立？真问题还是制造出来的问题？

### 2. Insight 与理论依据
- 核心 insight（作者「看到了什么别人没看到的」）
- 理论/方法论根基（Gödel Machine、开放式进化、元学习、自博弈、质量-多样性算法……）
- 该依据是**严格使用**还是**隐喻借用**？指出替换了什么、丢掉了什么保证
- insight → 方法之间是否存在逻辑跳跃？

### 3. 方法

#### 3.1 系统骨架
- 主循环用伪代码式 3–7 步概括；关键公式保留原始形式

#### 3.2 关键设计（每个设计按三段式）
> **设计名**
> - 功能：它解决什么问题
> - 核心思路：具体怎么做的（关键函数/机制名）
> - 设计动机：为什么这样做（而非更简单的替代方案）

#### 3.3 【RSI 专项】可修改范围
勾选并描述系统实际能改什么：
□ 模型权重/参数　□ 训练数据/策略分布　□ prompt/上下文　□ 记忆/技能库
□ 工作流/多Agent结构　□ 自身源代码　□ 整个 harness（工具/中间件/评测器）　□ 训练脚本（含训练新模型）
- 修改的**载体**是什么（monkey patching / 代码仓库编辑 / DSL / 配置……）？
- **哪些部分固定不可自改**（这往往决定真实递归深度）

#### 3.4 【RSI 专项】RSI 实现程度
按 0–5 分级定位，并给出判级理由：
- L0 一阶改进：改进器固定，只改产物（如 ADAS、AlphaEvolve）
- L1 自举循环：模型生成数据改自身权重/行为，改进规则固定（如 STaR、Self-Rewarding）
- L2 改进者可替换、规则固定：改代码的 Agent 会换，但选择/接受规则人定（如 SICA、DGM）
- L3 完全自指：负责改进的算法本身也在可修改范围内（如 Gödel Agent 的 π 与 I 同时更新）
- L4 自指 + 开放进化：自指之上维护多样性种群/档案库
- L5 权重与脚手架联合递归：自修改延伸到训练过程本身

### 4. 实验

- **Benchmark**：用了什么任务？选择集与报告集是否分离？任务是否可自动验证？
- **Baseline**：手工基线 / 自动基线 / 消融基线各有哪些？是否公平（同底座模型、同预算）？
- **协议**：初始条件、迭代次数、独立运行次数、并行度、成本
- **主结果表**：原文数字（注出处），**每列最优值加粗**
- **消融表**：附 Δ 列（相对 Full 配置的差值）；注明每个消融证明了什么、**缺哪些本该做的消融**
- **关键发现**：每条一个加粗结论 + 数字锚点
  （格式示例：「**Error Handling 是持续改进的前提**：去掉后 MGSM 掉 14.8 个点」）

### 5. 【RSI 专项】评估与测评依据（评估三问）

#### 5.1 内部判据：模型怎么判断修改「成立」？
- 接受机制类型：□ 门控式（分数不降才接受）　□ 选择式（全部入档，靠选择压力淘汰）　□ 无判据
- 效用函数/适应度是什么？含哪些项、权重多少？
- LLM 判断在哪个环节介入（提案端 / 验收端 / 两者）？
- 修改失败如何处理（回退 / 丢弃 / 留档）？

#### 5.2 外部审计：怎么判断 RSI 系统成功改进？
- 有无留出测试集？有无跨模型/跨基准/跨任务的迁移检验？
- 有无独立重复运行的方差报告？单次还是多次运行？
- 有无与人类设计 SOTA 的对照？
- 基线分数是否被自身设计人为压低？（如超时、弱初始 prompt）

#### 5.3 量化方式：改动如何被度量？
- 逐迭代轨迹 / 修改清单编目 / 归因对齐（每段提升能否对应到具体改动）
- 成本-效率指标（$/迭代、token、墙钟时间、评测精度分配策略）
- 质性证据（案例研究、轨迹审计、发现的新机制）
- **评估器失效案例**：有无 reward hacking / 过拟合验证集 / 记忆污染的证据或讨论？

### 6. Contribution 与结论
- 作者自陈的贡献（逐条）
- 你的判断：哪条贡献站得住、哪条夸大？
- 本文结论在其证据范围内是否成立？

### 7. 缺点与攻击面
- 作者自陈的 limitations 与 future work
- **你识别的额外缺点**（至少 2 条，覆盖方法/实验/评估不同层面）
- 本文最可能被后续工作攻击的点是什么？

### 8. 在 RSI 谱系中的定位
- 前置依赖（建立在哪几篇之上）与后续影响（谁直接继承/攻击它）
- **vs 对比**：覆盖 2–4 篇最相关工作，每条格式「vs X：相同点…，关键差异…」
- 一句话历史定位
- 参照系对比表：**哥德尔主线论文**固定与 Gödel Agent / SICA / DGM 对比；**其他路线论文**改与本路线 2–3 篇代表作对比

|---|---|---|---|---|
| 可修改范围 | | | | |

### 9. 批判性问题清单（供组会讨论）
3–5 个能刁难作者的提问，每个注明针对论文的哪一节、预期暴露什么弱点。

反向地，有三处约定是**笔记先于模板**的，v2.0 也还没收录：

1. **「0. 论文元信息」在实际写作中多写成「0. 速览卡片」**——把一句话总结、所属领域、RSI 分级、
   核心机制、内部判据、关键数字、关键局限压成一张两列表，便于跨篇扫读；卡片式笔记仍用元信息式写法。

2. **RSI 分级在 L0–L5 之间补了中间档**——模板的 3.4 节给整数 L0–L5，实际笔记使用了
   `L0.5`（边界形态）、`L1-` / `L1+`（记忆持久化 / 判据共进化）、`L1.5`（课程自产）、
   `L2.5`（开放式档案库）等细分档。完整图例见[总索引](index.md#rsi-grades)。
   分级是**本系列自用**的横向坐标，不等于任何单篇论文的自陈定位。

3. **节数随阅读深度分三档**——不是每篇都写满 0–9 节。完整精读写满 10 节；简读写到第 4 节；
   卡片式写到第 2 节。档位在[总索引](index.md)逐行标注，`scripts/check_notes.py` 按档位校验，
   档位不同不算「缺小节」。写作规则见下文。

### 写作与校验约定

- **档位声明**：卡片式笔记请在开头几行写明「**（卡片式）**」，校验脚本据此按卡片档检查。
- **非 arXiv 声明**：开源项目、实验室立场报告、Preprints.org 预印本等非 arXiv 文献，
  在头部写明「**非 arXiv**」或「**无 arXiv**」，即可豁免「缺 arXiv 号」提示。
- **头部元信息**：`scripts/extract_refs.py` 从笔记开头 25 行抽取文献元数据，四种历史格式均兼容，
  新笔记推荐用 `## 0.` 加 `- **标题**：/ **作者**：/ **发表**：` 的字段式写法。
- **新增一篇的完整流程**见 [README 的「新增一篇精读」](https://github.com/zlven/RSI-Papers-Reading#新增一篇精读)。
