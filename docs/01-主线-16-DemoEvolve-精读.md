## 1. 研究背景与动机

**领域位置**：harness 进化（2026 浪潮）的**批判性审视**。此前工作（Meta‑Harness 等）在反馈可归因（attributable）的任务上报告了成功，但论文指出一个未受审视的问题：

> 当任务是**长程、随机、终局稀疏计分**时（如 Roguelike 卡牌游戏 Balatro），rollout 反馈的归因性崩塌——稀疏终局分数无法指明哪一步、哪个 harness 机制该负责。

**核心问题**：
1. 自演化 harness 搜索在稀疏反馈下何时失效、如何失效？
2. 人类示范能否把搜索问题变容易？

**动机特征**：这是一篇**失败模式优先**的论文——先解剖失败，再给方案。在普遍报告正结果的 harness 进化文献中，其方法论自觉尤为突出。

---

## 2. 核心 Insight 与理论依据

### 2.1 关键洞察

1. **噪声选择失败模式**（noisy‑selection failure）：同种子 rollout 方差 + 复合轨迹漂移，使稀疏分数**偏好不活跃或非因果的 harness 编辑**——表观增益可以来自一个**从未触发的 hook**（实现错误），选择机制无法区分"真改进"与"噪声赢家"。
2. **示范的价值在于保持 state–action 对应**：人类轨迹保存了"在什么状态做什么动作"的对应关系，帮助编码提案器**把胜任行为翻译为可复用的、状态条件的 harness 机制**——这是稀疏失败信号无法提供的正向证据。
3. **正例控制（positive control）实验设计**：先用短程、可归因的 Liar's Dice 验证外循环机制本身能工作，再上 Balatro 暴露稀疏反馈的失败——把"机制失败"与"环境失败"分离。

### 2.2 理论依据与方法论谱系

- 无形式理论；方法论根基：**对照实验设计**（正例控制、开发/held‑out 分割、成对种子控制）+ **审计文化**（对选中候选做渲染级实现审计）。
- 谱系：外循环提案器沿袭 Meta‑Harness；示范注入呼应模仿学习/RLHF 中的专家轨迹思想。

### 2.3 与已有工作的联系

- **Meta‑Harness**：被用作自演化条件的实现，也是被审计的对象——论文的发现直接限定了其适用边界；
- **BalatroLLM**：Balatro 环境的基线智能体；
- 结论对全领域：任何用稀疏分数做选择信号的 harness/智能体进化工作都受影响。

## 3. 方法详解

### 3.1 DemoEvolve 框架

- **基础**：自演化外循环（提案器围绕冻结模型修改 harness；候选仅从开发 rollouts 中选择）；
- **增强**：提案器额外接收**人类交互轨迹** T^human = {(τ_j^H, C_j^H)}——τ 为人类 gameplay 轨迹，C 为可选的人类解说（commentary）；
- 人类轨迹作为**提案器侧的参照经验**，用于 harness 级诊断与编辑——不是直接训练数据，而是**诊断参照**。

### 3.2 可修改范围（RSI 视角）

| 层级 | 触及？ | 说明 |
|---|---|---|
| harness（观察解析/合法动作守卫/出价修复/概率估计/阈值策略/安全覆写） | ✅ | Liar's Dice 中进化出的典型机制清单 |
| 模型权重 | ❌ | 冻结 |
| 提案器规则 | ❌ | 固定 |
| 评估判据 | ❌（但被审计） | 论文的主要贡献恰是审视判据可靠性 |

### 3.3 RSI 实现程度

- **闭环**：存在（外循环进化）；
- **自我性**：弱（外置提案器 + 人类示范）；
- **分级**：**L1+**。本文的价值不在 RSI 深度，而在给整个 harness‑RSI 谱系提供了**失败模式目录与审计方法**。

## 4. 实验设计

### 4.1 环境

| 环境 | 角色 | 特征 |
|---|---|---|
| TextArena Liar's Dice（Small3 / OneCall‑Wild1 两变体） | **正例控制** | 短程、反馈可归因 |
| Balatro | **压力测试** | 长程、随机、稀疏终局计分 |

- 目标/对手单元：GPT‑5.4‑low 自对弈、Qwen‑3.5‑4B vs GPT‑5.4‑low、Qwen 自对弈；
- **评估协议**：候选仅用开发 rollouts 选择（N=5 或 10 个逻辑种子）；held‑out 用**不相交种子 + 成对方控制 + 30 个逻辑种子**；预声明的平局打破规则（不碰 held‑out）——统计纪律远高于领域惯例。

### 4.2 RQ1：自演化何时够用？（Liar's Dice）

- **全部六组主对比在 held‑out 种子上均提升**；
- **机制分析**：进化出的 harness 反复添加任务特定结构——观察解析、合法动作守卫、出价修复、概率估计、期望值叫牌阈值、开局策略、保守安全覆写——**不是"更长的 prompt"**；
- **边界适应**：弱模型（Qwen Small3）的 harness 演化为**近符号化的阈值策略**（代码接管决策）；强模型/难变体保留**神经‑符号分工**（代码管合法性/概率/风险，模型管残余战略判断）——harness 进化在自动重画"模型‑代码边界"。

### 4.3 RQ2：Balatro——稀疏反馈误导长程搜索

- **表观现象**：Meta‑Harness（自演化条件）ID 种子均分 17.00→19.33、完成数 3/9→4/9；
- **审计拆穿**：OOD 种子 16.83→16.33（不迁移）；选中的候选包含一个**意图中的动态 hook，但因实现错误从未触发**——"表观 ID 增益不是被验证的功能性改进，而是高方差 rollout 评估下的噪声候选选择"；
- **DemoEvolve**：同预算下，示范引导产生**活跃的模型面向编辑**，held‑out 泛化更一致，且诊断证据支持**更好的编辑定位**。

### 4.4 消融/对照

- 自演化 vs 文本引导变体 vs DemoEvolve：DemoEvolve 在 Balatro 上优于两者；
- BalatroLLM 基线：完成 5/15 rollouts。

## 5. 评估和测评依据（评估三问）

### Q1 内部判据：怎么判断"编辑成立"？

- **基础机制**：开发集分数选择（继承 Meta‑Harness 的选择式判据）；
- **本文的批判**：该判据在稀疏反馈下**失效**——选择信号与因果改进脱钩；
- **本文的修补**：示范把诊断从"猜失败原因"变为"参照胜任行为"，间接修复判据的信息质量；并引入**实现审计**（hook 是否触发、派生状态是否计算并注入、模型调用接口是否变化）作为判据的补充层。

### Q2 外部审计：怎么判断系统确实在改进？

- **ID/OOD 双种子分割**：表观 ID 增益必须过 OOD 关——Balatro 案例显示这道关能拆穿假改进；
- **成对控制 + 30 逻辑种子**：统计功效设计；
- **渲染级审计**（Appendix C.3）：对选中候选做逐帧实现检查——这是全部精读对象中最深的"改动真实性"审计。

### Q3 量化方式：如何度量改动？

- **活跃性审计**：不只报告 diff，还验证 diff **是否真的在运行时被激活**——"改动存在 ≠ 改动生效"；
- **机制编目**：Liar's Dice 的七类进化机制清单是改动归因的良好示范。

**评估三问总评**：本文是对评估三问的**元贡献**——它证明：在稀疏反馈下，Q1 的选择判据可能系统性失灵，Q2 需要 OOD 种子与实现审计双保险，Q3 必须验证改动的运行时活跃性。任何后续的 harness/智能体进化工作都应过这套审计。

## 6. 实验结果与分析

- **正例**：Liar's Dice 六组全胜 + 机制编目 + 模型‑代码边界的自适应重画（弱模型符号化、强模型分工化）——后者是颇具理论趣味的发现；
- **反例**：Balatro 的"hook 未触发"审计——成为 RQGM/RRSI 等同期工作引用的标志性警示案例；
- **DemoEvolve**：在最难设置下以示范注入取得更稳定的进化。

---

## 7. 结论与意义

- **结论**：自演化 harness 进化在反馈可归因时有效；稀疏长程任务中会被噪声选择劫持；示范注入通过保持 state–action 对应，使搜索更省样本、可诊断、稳定。
- **领域意义**：为 harness 进化文献补上**自我批判**的一课；其审计协议（ID/OOD 种子 + 活跃性检查）应成为该领域的最低标准。
- **局限（论文自列）**：
  1. 任务覆盖窄——回合制游戏（Liar's Dice + Balatro），"通往广泛任务世界适应的第一步，而非直接迁移的证据"；
  2. 假设人类示范能与智能体的观察‑动作接口对齐——接口不同则对齐困难；
  3. 对不完美示范的鲁棒性未测。

## 8. 未来方向（基于原文 §6）

1. 跨接口的轨迹对齐；
2. 不完美/低质量示范下的鲁棒性；
3. 向工具使用、终端任务、网页智能体、具身环境的迁移检验。

## 9. 批判性问题清单（精读者视角）

1. **人类示范的可得性**：Balatro 有现成玩家社区；软件工程、科研等目标域的高质量示范成本几何？方法的适用范围受示范经济学制约。
2. **正例控制的选择偏差**：Liar's Dice 作为"可归因反馈"代表是否过于理想？多数真实任务介于两极之间，失效的相变点在哪？
3. **审计的可扩展性**：渲染级审计每个候选都做一次不现实；能否自动化"hook 活跃性检查"？
4. **噪声选择的统计修补 vs 信息修补**：DemoEvolve 走信息修补（示范）；增大 N、成对评估等统计修补是否更便宜？两者未正面对照。
5. **提案器对示范的利用深度**：示范是"参照"还是会被生搬？论文未分析示范被滥用（过度模仿人类而非适应模型能力）的风险。
