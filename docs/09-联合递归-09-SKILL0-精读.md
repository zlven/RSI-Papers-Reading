## 1. 动机漏斗：六步走到问题

1. **大目标**：增强 LLM agent 的程序性能力。
2. **现状**：Agent Skills（结构化程序知识 + 可执行资源，推理时动态加载）已是可靠机制。
3. **裂缝三处**：(a) 检索噪声引入无关指导；(b) 注入的技能内容造成大量 token 开销；(c) **模型从未真正获得知识，只是在遵循**——技能是外挂，不是能力。
4. **问题**：技能能否内化进参数，实现 zero-shot 自主行为，推理时零检索？
5. **约束**：直接撤掉技能训 RL 会崩（模型依赖它）；全部保留则学不到自主行为。
6. **本文问题**：设计训练期课程，让技能上下文从"全额供给"平滑过渡到"完全撤回"，且撤回顺序由 on-policy 有用性驱动。

## 2. Insight 与理论依据

### 核心 Insight

技能上下文的本质是**训练期的拐杖（crutch）**：有用但应逐步撤掉，且**撤哪个、何时撤应由当前策略的实际受益决定**，而不是固定时间表。

Dynamic Curriculum 的判据是 *on-policy helpfulness*：只有当前策略仍能从中受益的技能文件才保留——这与课程学习的"按能力配难度"一致，但方向相反：不是逐渐增加材料，而是**逐渐撤回支架**，预算线性衰减到 zero-shot。

### 与 Harness-Zero 的对照

同属"运行时组件 → 权重"的蒸馏模式，对象不同：Harness-Zero 蒸馏 harness 诱导的**行为**，SKILL0 内化技能库的**内容**；Harness-Zero 的对齐难题在动作空间，SKILL0 的在上下文依赖。SKILL0 终态更激进（完全 zero-shot，连固定 harness 都不强调）。

## 3. 方法拆解（摘要可推断部分）

### 关键设计

**设计 1：渐进撤回课程（progressive withdrawal）**
- 功能：训练从完整技能上下文开始，逐步撤回，终态 zero-shot。
- 设计动机：直接撤掉技能 = 分布突变 → RL 崩；渐进撤回 = 课程平滑。

**设计 2：Dynamic Curriculum（on-policy 有用性筛选）**
- 功能：评估每个技能文件对**当前策略**的边际有用性，只保留仍受益的，在线性衰减预算内。
- 核心思路：技能的有用性随策略成长而变化——静态课程会保留已学会的技能（浪费 token）或过早撤掉未学会的（崩）。on-policy 筛选使撤回顺序自适应。
- 设计动机：这本质是"支架的自适应拆除"，与发育机制中参照物退出同构。

**设计 3：紧凑视觉上下文渲染**
- 功能：技能离线按类别分组，与交互历史一起渲染成紧凑视觉上下文，教工具调用和多轮完成；最终每步 <0.5k token。
- 备注：视觉上下文这个选择不寻常（把文本技能渲染成图像？），省 token 的动机明确，但机制细节待全文。

## 4. 实验声称（摘要数字，未核）

| Benchmark | 相对标准 RL 基线 |
|---|---|
| ALFWorld | +9.7% |
| Search-QA | +6.6% |
| WebShop | +10.1% |

上下文效率：每步 <0.5k token（对比技能注入式的典型开销应为数 k——效率声称是核心卖点之一）。
**疑点**：基线是"standard RL"（无技能的 RL）还是"技能注入推理"？若只对比前者，则未回答"内化 vs 推理时检索"的正面比较——而后者才是动机里批判的对象。三个 benchmark 均为经典 agentic 环境，与 harness 文献的 SWE-bench 系不同，横向不可比。

## 5. 评估三问

**Q1 内部标准**：任务成功率 + token 效率双指标；on-policy helpfulness 作为课程内部信号（自指度：策略评估自己的学习材料——温和的内部标准，但有外部任务奖励兜底）。
**Q2 外部审计**：开源可复核；seed/方差信息未知；三个公开 benchmark。
**Q3 量化**：token 开销量化（<0.5k/步）是少见的成本意识；但训练成本（Dynamic Curriculum 的评估开销）未报。

## 6. Contribution 提炼

1. **技能内化的形式化**：把"推理时技能增强"的三宗罪（噪声/开销/未习得）变成可解的训练问题。
2. **Dynamic Curriculum**：on-policy 有用性驱动的支架撤回——课程设计从供给侧（材料难度）转向需求侧（策略受益）。
3. **效率-性能双声称**：涨点的同时把上下文压到 <0.5k token/步——若成立，是"内化优于外挂"的经济学证据。

## 7. 缺点与攻击面

1. **缺少正面对照**：内化后 vs 推理时保留技能检索——摘要的三个数字都是 vs 标准 RL，未 vs 技能增强推理。若检索版仍更高，"内化"的定位应是压缩/效率手段而非能力手段。
2. **技能固化**：内化进权重的技能随权重冻结；技能库更新需要重训——外挂技能的可更新性优势被放弃，何时值得内化是未答的边界问题。
3. **泛化**：内化是记住技能内容还是学会使用程序性知识？对未见技能的组合泛化无摘要证据。
4. **视觉上下文的必要性**：渲染成视觉上下文的消融待查——是否只是 token 压缩技巧？

## 8. 谱系定位

**在 12 篇分类中**：D 蒸馏模式第二篇（与 Harness-Zero 并列）；与 SEAL（自编辑微调数据）同属"权重吸收外部知识"家族，但 SEAL 的自编辑由模型自己生成，SKILL0 的技能是外部给定的——SKILL0 没有自指结构。

**对你的研究**：SKILL0 的价值在**课程机制可迁移**：Dynamic Curriculum 的"on-policy 有用性筛选"可以直接搬到 harness 进化——harness 组件的保留/淘汰也应由当前策略的边际受益决定（对照：DGM 的存档准入是"能编译+能编辑"，与策略受益无关）。这是跨路线移植的候选点。

## 9. 批判性问题清单

1. 内化 vs 推理时检索的正面比较数字是多少？（决定定位：能力手段还是效率手段）
2. Dynamic Curriculum 的 helpfulness 怎么测？每步对每个技能文件做一次 on-policy 评估的成本是多少？
3. 内化后的模型面对**技能库未覆盖**的任务，退化到什么程度？（外挂版可以即时加新技能，内化版不能）
4. 视觉上下文 vs 纯文本压缩的消融？
5. 撤回顺序学到的模式（哪些技能先撤/后撤）有可解释的规律吗？——这是课程机制最有信息量的副产品。
