## 1. 研究背景与动机

**领域位置**：PEFT（参数高效微调）。传统微调的问题：计算昂贵、且**静态**——一套适配参数应对所有任务。

**核心问题**：能否让 LLM **在推理时**针对每个未见任务**实时**调整自己？

**与 SEAL 的对照定位**：SEAL 走"持久权重更新"路线（改了就留下）；Transformer² 走"运行时调度"路线（什么都不留，每次都临时调配）。两者构成权重层适应的光谱两端。

## 2. 核心 Insight 与理论依据

### 2.1 关键洞察

1. **奇异值是任务知识的"旋钮"**：权重矩阵的奇异分量承载任务相关结构；只调奇异值（而非全矩阵或低秩增量）即以极少参数获得任务适应——**SVF**；
2. **两遍推理**：pass 1 用调度系统（dispatch）识别任务性质；pass 2 把 RL 训好的任务特定**专家向量**（z 向量，缩放奇异分量）动态混合后应用；
3. **RL 训练专家向量**：每个任务的专家向量用 RL 训出（奖励 = 任务表现），比 SFT 更不易过拟合（论文主张）；
4. **受神经科学启发**（论文讨论）：大脑按任务招募不同回路——专家向量的动态混合是其工程对应。

### 2.2 方法论谱系

- SVD 参数化 + MoE 思想 + RL 微调的组合；
- 与 Text‑to‑LoRA（生成适配器）等同期工作同属"适配器按需获取"方向，但 Transformer² 的粒度更细（奇异分量级）。

## 3. 方法详解

### 3.1 框架

**离线**：
- 对每个训练任务，用 RL 训练一个专家向量 z（对权重矩阵奇异值的缩放系数）——SVF；
- 训练调度系统（三种实现变体：prompt 工程/专用调度 LLM/分类器）。

**推理（两遍）**：
1. pass 1：调度系统分析输入，识别任务性质；
2. pass 2：按识别结果**动态混合**专家向量（加权组合），应用于权重奇异分量，生成回答。

### 3.2 可修改范围（RSI 视角）

| 层级 | 触及？ | 说明 |
|---|---|---|
| 权重（推理时） | ⚠️ 临时 | 奇异分量被**临时**缩放；推理结束即还原——非持久修改 |
| 权重（离线） | ✅ | 专家向量由 RL 训练（但那是离线训练，非自我改进） |
| 调度策略 | ❌（运行时） | 固定 |
| 改进循环 | ❌ | 不存在——无反馈积累、无新专家诞生 |

### 3.3 RSI 实现程度

- **无改进闭环**：系统在部署中不产生新知识、不更新专家库；
- **分级**：**L0.5（运行时自适应）**。列入本精读系列作为**边界标本**：名字里有 "self‑adaptive"，但"self"指"无需人工干预地按需调配"，而非"改进自身"——这正体现了 2607.07663 综述批评的"self‑ 词汇混淆"。

## 4. 实验设计

- **任务**：数学（GSM8K/Math）、编码、推理、知识问答等多类未见任务；视觉‑语言任务（LLaVA 架构）；
- **基线**：LoRA（主要对照）及其他 PEFT；
- **结果**（摘要级）：以更少参数超越 LoRA；跨 LLM 架构与模态有效；
- **分析**：SVF 比 LoRA 更抗过拟合；专家向量可组合（混合权重随任务性质平滑变化）。

## 5. 评估和测评依据（评估三问）

- **Q1**：不适用（无改进循环）；RL 训练专家向量时的奖励 = 任务表现（离线门控）；
- **Q2**：未见任务上的泛化测试是主要审计；跨架构/跨模态复现；
- **Q3**：改动即专家向量的混合权重——可解释性好（可观察"当前输入激活了哪些专家"），这是该路线罕见的审计优势。

## 6. 结论与意义

- **结论**：奇异分量级的运行时自适应，以极少参数实现对未见任务的实时定向行为。
- **意义**：证明了"适配器的发现与组合"可以完全离线化、推理时零训练——与 SEAL 互补的两个极端；
- **局限**：专家库覆盖之外的任务无能为力；调度错误级联；无终身积累；**不是自我改进**（本系列将其作为概念边界标本）。

## 7. 未来方向（原文提及）

- 模型合并与自适应的规模化；专家库的持续增长机制（那将真正接近自我改进）。

## 8. 批判性问题清单

1. **"self‑adaptive"的命名是否夸大**？无新知产生、无闭环——命名贡献了"self‑"词汇的通货膨胀；
2. **专家库的覆盖经济学**：N 个任务需要 N 个 RL 训练的专家；长尾任务的获取成本如何？
3. **混合的语义**：对输入加权混合多个任务专家，理论上等价于假设任务空间是凸组合结构——该假设的失败模式（复合新任务）未充分压力测试；
4. **与 SEAL 的合体**：运行时调度（Transformer²）+ 持久内化（SEAL）的混合架构是否两全？两文均未探索。
