# RSIBench-Data 精读报告

> 按 RSI 论文精读模板 v1.0 生成

## 0. 论文元信息

- **标题**：RSIBench-Data（以数据为中心的递归自我改进基准）
- **作者**：Fanqing Meng 等
- **发表**：arXiv:2607.25886（2026 年 7 月），开源
- **一句话总结**：把"研究决策"从训练栈/服务/评测的纠缠中隔离出来的第一个受控 RSI 基准——基础设施全部钉死，只让 Agent 做数据级研究决策。
- **速读结论**：本系列中评估方法论价值最高的工作之一；两个主数字（58.33% 首轮改进率 / 78.26% 峰值后退化率）已成为反驳乐观 RSI 声明的标准弹药。必读。

## 1. 方向与领域 → 动机

- **子领域**：RSI 评测基准（回路层）。
- **背景**：2025–2026 年大量系统宣称"自我改进"，但已有评测把研究决策与优化器、服务、系统实现纠缠在一起，无法干净地回答：**Agent 能不能做"以数据为中心的研究"**——诊断能力缺口、设计训练数据策略、从 checkpoint 反馈中学习？
- **核心研究问题**：在基础设施完全固定、全程可审计的条件下，前沿 Agent 的数据级自我改进能力到底处于什么水平？
- **动机是否成立**：成立且切中要害。它把"改进回路"第一次变成了可审计对象，而非论文里的黑箱。

## 2. Insight 与理论依据

- **核心 insight**：**受控性优先于真实性**——只有把目标模型、训练接口（Tinker）、评测服务（Harbor/E2B 沙箱）、预算、外部 rollout 模型全部冻结，"基础设施变化"才能与"研究进展"分离，改进轨迹才可归因。
- **理论根基**：实验方法学的析因思想；与 METR 的 matched-budget 原则一脉相承。
- **逻辑跳跃**：数据级 RSI 只是 RSI 的一个切片，结论不能外推到代码级/权重级联合递归——论文自己明确了这一点。

## 3. 方法

### 3.1 基准设计

- **4×6 矩阵**：4 个前沿 researcher agent（Claude Code + Opus-4.8 / Sonnet-5；Codex + gpt-5.6-sol / gpt-5.6-terra）× 6 个目标基准（SWE-bench Verified/Multilingual/Pro、GPQA Diamond、AIME 2026、Terminal-Bench 2.0）；
- Agent 每轮提交"训练数据 + 白名单配置"，训练栈执行微调，官方基准原生分数作主指标，辅以改进轨迹、成本、wall-clock；
- 外部 rollout 模型固定为 Claude Opus 4.8——连"生成长什么样"都被控制。

### 3.2 【RSI 专项】可修改范围

- ☑ 训练数据配方（Agent 的研究决策）
- ☐ 目标模型　☐ 训练栈　☐ 评测环境　☐ 评测代码　☐ 预算

### 3.3 【RSI 专项】RSI 实现程度

**判级：测量对象对应 L3（固定改进机制内的自主改进闭环）。** 基准本身的设计完整性恰恰依赖于把回路其余部件钉死——这是它"能审计"与"不能认证高等级 RSI"的一体两面。

## 4. 实验设计

- 24 个主运行（4 Agent × 6 基准）+ 资源分析 + 推理力度消融 + 一个探索性 RSI 彩蛋实验（Kimi K2.6 同时当研究员与靶模型，SWE-bench Pro，20h/$2000 预算）；
- Baseline：未适配的基座模型官方分数；
- 主结果：
  - **58.33%** 的设定中首轮有效尝试即有改进（发现能力已具备雏形）；
  - 达到峰值后继续搜索的实验中 **78.26% 以更差结果收场**，其余仅追平峰值——**改进非单调**；
  - 无 Agent 全面占优：Codex gpt-5.6-sol 领先 3 个非 SWE 基准，3 个 SWE 类任务由 3 个不同 Agent 分别拿下——任务族相似性不产生稳定排名；
  - 若干 checkpoint 训练后**低于基座**（GPQA Diamond、SWE-bench Multilingual）——数据策略可以中性甚至有害；
  - 资源分析：中位 6.55 小时 / $62.51，跨度 $4.80–$363.77；高分≠高成本（GPQA Diamond 65% 只花 $10.37）；
  - 推理力度消融：Sonnet-5 从 high→max effort，前四次尝试均分 35.5%→44.0%，官方分 35%→52%，机制是"深度换广度"（候选更少但数据集更大，149 vs 50 条记录）；
  - 彩蛋实验：Kimi K2.6 七轮 LoRA 尝试策略明显演化，最终 22% 仍低于未适配参照 33%——**策略在进化，模型没有效改进**。

## 5. 【RSI 专项】评估与测评依据

### 5.1 内部判据

- **执行反馈 + 外部神谕混合**：Agent 内部用选择集分数做搜索信号，官方基准原生分数做最终裁决；两者分离是"发现-可靠性鸿沟"能被观测的前提。

### 5.2 外部审计

- 极强：基础设施固定、沙箱评测、预算声明、成本与轨迹全公开；
- 反复出现的失效模式被系统编目：误诊目标能力、生成错位监督、越过强 checkpoint 继续搜、无法把新反馈转化为更好策略。

### 5.3 量化方式

- 官方原生分数 + 完整代际轨迹（而非端点）+ 成本/wall-clock 联合报告——"分数×成本"二维解读是本文的方法论贡献之一。

## 6. Contribution 与结论

- **自陈贡献**：①首个受控的数据级 RSI 基准；②发现-可靠性鸿沟的定量刻画；③配套开源基础设施。
- **我的判断**：②最持久——"能改进一次"与"能持续改进"被证明是两个能力层级，此后任何只报单轮改进的声明都不可信。
- 结论克制：Agent 已具雏形但不可靠；失败诊断能力是当前最稀缺环节。

## 7. 未来方向与缺点

- **作者自陈**：扩展到代码级/架构级修改；多运行降低单运行噪声。
- **额外缺点**：
  1. 只覆盖数据级 Target，无法回答回路更深层的问题；
  2. 单运行代表性分数有噪声，部分结论的统计功效有限；
  3. 压力测试发现的轨迹未必代表所有可能轨迹。
- **最可能被攻击的点**：Target 维度单一——批评者会说"数据级 RSI 的瓶颈不代表 RSI 的瓶颈"。

## 8. 在 RSI 谱系中的定位

- **前置**：RE-Bench/MLE-bench（能力代理）的"回路黑箱"局限是它的问题来源；与 PostTrainBench 并称 2026"回路审计期"的两大基准。
- **后续**：为"有效 L5"判定提供了方法学组件（受控栈 + matched-budget + 轨迹审计）。
- **一句话定位**：RSI 评测从"能力代理"转向"回路审计"的标志性工作。

## 9. 批判性问题清单

1. 78.26% 的退化率是 Agent 能力的上界，还是固定栈（Tinker/白名单配置）约束下的人为产物？换一个允许改训练配置更多的栈，数字会变吗？
2. "峰值后退化"的最优停机判据是什么？基准本身没有给出——这是它留给后续研究的最大问题。
3. 4 个 Agent 全部来自两家实验室（Anthropic/OpenAI 系脚手架），结论对开源 Agent 的泛化性如何？
4. 外部 rollout 模型固定为 Opus 4.8——如果 rollout 模型换成被改进模型自身（真递归），失效模式会变吗？
