## 1. 研究背景与动机

**领域位置**：编程智能体工程。harness（模型与工具/执行环境之间的中介层）已成为编程智能体性能的核心，但 harness 工程仍是**手工技艺**。

**自动化面临的三大挑战**（论文问题陈述）：
1. **异质动作空间**：可编辑组件五花八门（工具、中间件、记忆、prompt……），修改空间没有统一表示；
2. **信号淹没**：原始轨迹动辄数百万 token，可行动的信号被埋没；
3. **归因困难**：一次编辑的效果难以与性能变化挂钩。

**核心主张**：这三 challenge 本质上是**可观测性问题**——对症下药的做法不是更强的优化器，而是给进化循环装上"仪表盘"。

---

## 2. 核心 Insight 与理论依据

### 2.1 关键洞察

1. **每次编辑都是一张可证伪契约**：编辑必须附带**自我声明的预测**（"这处修改将改善某类结果"），下一轮用任务级结果验证——预测失败即证伪，编辑无法靠噪声混进 harness。
2. **经验必须被蒸馏成可消费的形式**：百万级 token 的原始轨迹对进化智能体不可用；分层、可下钻的证据语料（layered, drill-down evidence corpus）才是有效输入。
3. **组件需要文件级表示**：每个可编辑组件有明确文件表示，动作空间由此**显式且可回滚**（explicit and revertible）。

### 2.2 理论依据与方法论谱系

- 方法论根基是**软件工程的可观测性（observability）思想**向进化计算的迁移：监控 → 假设 → 验证 → 回滚。
- "可证伪契约"呼应科学方法（波普尔）与假设驱动开发（hypothesis-driven development）。
- 在谱系上属于 2026 年 harness 进化浪潮中**工程纪律最强**的一支：与 Self-Harness 的回归门控相比，AHE 进一步要求**预测先行**。

### 2.3 与已有工作的联系（按摘要）

- 基线对照：人工设计的 **Codex-CLI** harness、自进化基线 **ACE** 与 **TF-GRPO**；
- 与同期 Self-Harness、Meta-Harness 同属 harness 自动进化阵营，差异在机制设计（可观测性三支柱）。

---

## 3. 方法详解

### 3.1 三大可观测性支柱

| 支柱 | 机制 | 解决的挑战 |
|---|---|---|
| **组件可观测性** | 每个可编辑 harness 组件获得**文件级表示** | 异质动作空间 → 显式、可回滚 |
| **经验可观测性** | 把数百万原始轨迹 token **蒸馏为分层、可下钻的证据语料** | 信号淹没 → 可消费输入 |
| **决策可观测性** | 每次编辑**配对一条自我声明的预测**，下一轮按任务级结果验证 | 归因困难 → 可证伪契约 |

闭环：观察 → 诊断 → 提案（附预测）→ 执行 → 验证预测 → 保留/回滚。

### 3.2 可修改范围（RSI 视角）

| 层级 | 本文触及？ | 说明 |
|---|---|---|
| 系统提示 | ✅ | 可编辑组件之一（但消融显示收益不主要来自它） |
| **工具** | ✅ | 消融定位的主要收益来源 |
| **中间件** | ✅ | 同上 |
| **长期记忆** | ✅ | 同上 |
| 权重 | ❌ | 冻结 |
| 进化机制自身（三支柱/契约协议） | ❌ | 固定 |

### 3.3 RSI 实现程度

- **改进闭环**：存在且纪律严明（契约制）；
- **改进器自身会被改进吗**：不会；
- **分级判定**：**L2**。标准的"自我脚手架改进"；其独特性不在修改深度而在**改进过程的审计质量**——预测-验证机制使每次改动都可追责。

---

## 4. 实验设计

### 4.1 设置

- **主基准**：Terminal-Bench 2（10 轮 AHE 迭代）；
- **迁移测试**：SWE-bench-verified（冻结 harness，不重演化）；Terminal-Bench 2 上换三个不同模型家族；
- **对照**：Codex-CLI（人工设计 harness）、ACE、TF-GRPO（自进化基线）。

### 4.2 主结果

（摘要）

| 项目 | 数值 |
|---|---|
| Terminal-Bench 2 pass@1 | 69.7% → **77.0%**（10 轮） |
| Codex-CLI（人工 harness） | 71.9%（被超越） |
| SWE-bench-verified 迁移 | 聚合成功率第一，且 token 比种子 harness **少 12%** |
| 跨模型家族迁移（3 个家族） | **+5.1 ~ +10.1 pp** |

**关键解释**（摘要原文）：冻结 harness 的跨家族迁移成功，"表明进化出的组件编码的是**通用工程经验**而非基准特定调参"。

### 4.3 消融

- 收益定位于**工具、中间件、长期记忆**组件，而非系统提示；
- 推论（摘要原文）：**事实性的 harness 结构可迁移，散文级的策略表述不可迁移**——这是对"prompt 优化 vs 结构优化"之争的直接证据。

## 5. 评估和测评依据（评估三问）

### Q1 内部判据：怎么判断"编辑成立"？

- **判断主体**：**预测-验证契约**——编辑附带的自我声明预测在下一轮被任务级结果检验；预测失败 = 编辑被证伪。
- **性质**：**门控式的强化形态**——不仅要求"改后变好"，还要求"改前说清为什么好"。这把无责猜改（trial-and-error）从机制上排除。
- **反馈机制**：证据语料（经验可观测性）支撑诊断质量。

### Q2 外部审计：怎么判断系统确实在改进？

- **人工 harness 对照**：超越 Codex-CLI 是"非自我陶醉"证据；
- **跨家族迁移 + 零重演化**：冻结 harness 直接在三个异质模型家族上正迁移——最强的"非过拟合"证据形式之一；
- **token 效率**：迁移后 token 反而减少 12%，排除了"靠堆上下文取胜"的解释。

### Q3 量化方式：如何度量改动？

- 改动 = 组件级文件 diff，天然可回滚、可编目；
- 消融把收益**定位到组件类别**（工具/中间件/记忆）——改动归因粒度优于多数同类工作。

**评估三问总评**：AHE 是评估纪律的样板：Q1 的可证伪契约、Q2 的跨家族零成本迁移、Q3 的组件级归因，三者相互咬合。其"事实结构迁移、散文策略不迁移"的消融结论本身就对全领域有方法论价值。

---

## 6. 实验结果与分析

- **主结果**：77.0% pass@1，超人工与自进化基线；
- **迁移性**：最强的论文卖点——进化产物是"通用工程经验"；
- **消融启示**：prompt 层的"策略散文"是过拟合重灾区，结构性组件（工具/中间件/记忆）才是迁移载体——为"改什么"提供了实证排序。

---

## 7. 结论与意义

- **结论**：可观测性是 harness 自动进化的关键缺失件；配上它，自动进化可以超越人工设计且产物可迁移。
- **领域意义**：在 harness 进化浪潮中确立了**审计质量标准**；其消融结论直接挑战"prompt 优化为主"的惯性，支持"结构性组件优先"。
- **局限（文本可见）**：摘要未报告成本、多种子方差；"通用工程经验"的迁移结论目前限于编程类任务。

---

## 8. 未来方向（基于论文贡献推断）

1. 迁移结论向非编程域（网页/具身）的扩展检验；
2. 可证伪契约机制与其他进化框架（DGM 式开放档案）的结合；
3. 预测失败案例的自动归因深化。

## 9. 批判性问题清单（精读者视角）

1. **预测的"自我声明"由谁书写**？若由同一 LLM 书写，预测质量本身成为隐性瓶颈——弱模型的预测会不会系统性偏差？
2. **契约证伪的统计门槛**：下一轮验证基于多少次任务级结果？噪声环境下"预测失败"与"运气不好"如何区分（所读材料未见）？
3. **69.7% 起点的 harness 是什么**？若起点已是强 harness，+7.3pp 的成色更高；摘要未明示种子 harness 的来源。
4. **跨家族迁移的对称性**：从 A 家族进化出的 harness 迁到 B 家族有效；反向是否成立？方向性未报。
5. **与 RRSI 揭示的病理的关系**：同期工作（RRSI）报告了基准记忆化、随机赢家锁定等 harness 进化病理；AHE 的契约机制能否天然免疫，需要正面检验。
