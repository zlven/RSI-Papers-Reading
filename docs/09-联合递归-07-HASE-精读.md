## 1. 动机漏斗：六步走到问题

1. **大目标**：自进化 agent 框架。
2. **现状**：自进化框架优化任务解，把外围 harness 当固定——与 HELIX 完全同一个裂缝。
3. **裂缝加深**：harness 不仅固定，还**可能有缺陷**（评估组件本身不完美），而框架没有任何机制发现和修复它。
4. **问题**：能否让**同一个模型**在同一个 agentic 过程中交替产出任务解和 harness 编辑，用 RL 统一训练？
5. **约束**：不依赖更大的 proposer 模型（对比基线是 GPT-OSS-120B+Claude Code 当 harness proposer 的重量级配置）。
6. **本文问题**：单模型统一动作空间（解任务 ∪ 改 harness）的 agentic RL，能否用小模型达到大模型+harness proposer 组合的水平？

## 2. Insight 与理论依据

### 核心 Insight

WHALE/Co-Harness/HELIX 的共进化都有**角色分工**（proposer 改 harness，task model 解任务，通常不同模型或不同模式）；HASE 的激进之处：**取消角色分工**——同一个模型、同一个多轮动作空间，这一步可以写任务解、下一步可以改 harness 组件。

理论含义：harness 编辑能力不再是外挂的 meta-agent 特权，而是**被 RL 直接塑造的策略行为**——模型学到的不只是"怎么解任务"，还有"什么时候该去改 harness 而不是继续解任务"。这个 meta-决策从规则（WHALE 的 patience、SIA 的 Feedback-Agent）变成了**可学习对象**。

## 3. 方法拆解（摘要可推断部分）

### 整体骨架

```
单一模型（Qwen3-8B）在多轮动作空间中：
  动作 ∈ {生成任务解, 编辑选定 harness 组件}
  agentic RL 统一训练 → 权重更新
  → 权重 × harness × 解 三对象共进化
```

### 关键设计（按摘要推断，待全文核实）

**设计 1：统一动作空间**
- 功能：harness 编辑与任务求解共用多轮动作接口。
- 设计动机：让"改 harness"成为策略内的原子动作，RL 奖励可以直接塑形 meta-决策。

**设计 2："选定"组件白名单**
- 注意摘要措辞是 *edit **selected** harness components*——不是全量自改写，是白名单内编辑。安全性和稳定性的显式妥协，与 Co-Harness 的五组件白盒、WHALE 的白名单同源。

**设计 3：不完美评估组件的修复**
- 摘要明确声称 *HASE also repairs imperfect evaluation components*——**评估器进入可修改范围**。这是 12 篇里除 RQGM 外唯一触碰评估器的工作，但机制相反：RQGM 是把评估器当共进化对象（防合谋），HASE 是把评估器当**可修复的缺陷组件**（修 bug）。一个防评估器腐败，一个修评估器错误——互补。
- 这也埋着风险：模型能改评估器，就能学会**把评估器改宽**（reward hacking 的终极形态）。摘要未提防护机制，全文必读点。

## 4. 实验声称（摘要数字，未核）

| 任务 | 声称结果 |
|---|---|
| 文本分类 | Qwen3-8B 匹配 GPT-OSS-120B + Claude Code harness proposer 组合 |
| alpha 因子挖掘 | 超过已报告的 GPT-OSS-120B 基线 |
| circle-packing 算法发现 | 修复不完美评估组件后收敛到 SOTA |

**摘要级疑点**：
1. "匹配 120B 组合"的基线公平性——Claude Code proposer 的成本与 HASE 的 RL 训练成本比过吗？
2. circle-packing 是 DeepMind AlphaEvolve 的标志性任务，"SOTA"指哪个数字？
3. 三个任务都是可验证奖励域（分类有标签、因子有回测、packing 有几何校验）——无验证器域的泛化无证据。

## 5. 评估三问

**Q1 内部标准**：可验证任务奖励 + **可编辑的评估组件**——Q1 本身进入动作空间，这是本篇最激进点，也是最危险点。门可改 = L4 特征，但摘要未见"门改动是否需要更高层授权"的机制。
**Q2 外部审计**：无法从摘要判断。alpha 因子"超过已报告基线"是与文献数字比还是复现基线比，待核。
**Q3 量化**：越级比较（8B vs 120B）隐含成本论点，但摘要无成本数字。

## 6. Contribution 提炼

1. **统一动作空间**：harness 编辑从外挂 meta-agent 变为策略内可学习行为——meta-决策学习化，比 WHALE 的规则切换、SIA 的固定 Feedback-Agent 都更端到端。
2. **三对象共进化**：权重 × harness × 解在同一 RL 循环，对象数超过所有交替式工作。
3. **评估器修复能力**：唯一声称能发现并修复评估组件缺陷的联合工作（与 RQGM 的防腐败互补）。
4. **小模型越级证据**（若成立）：8B 匹配 120B 组合，说明共进化对参数预算的杠杆可能比想象大。

## 7. 缺点与攻击面

1. **评估器可编辑 = reward hacking 直通车**：没有防护机制的"修复评估器"与"腐蚀评估器"是同一个动作。RQGM 的教训（锚门）在此直接适用——HASE 是否意识到这个攻击面是全文第一必读点。
2. **统一动作空间的信用分配**：奖励来自任务解，harness 编辑动作的收益是延迟的（改完 harness 后续解才受益）——长延迟信用分配在多轮 RL 里极难，摘要未提解法。
3. **三任务全可验证域**：无验证器域泛化未知。
4. **开源状态未知**——若闭源，8B 越级 120B 的强声称无法复核，可信度评级应下调。

## 8. 谱系定位

**HASE 在共进化家族中的位置**：

| 维度 | HASE | WHALE | HELIX | SIA |
|---|---|---|---|---|
| meta-决策 | **RL 学习** | 规则（patience） | 规则（三阶段） | 固定 Feedback-Agent |
| 修改者=执行者？ | **是（同一模型）** | 否 | 否 | 半 |
| 评估器可动 | **是（修复）** | 否 | 否 | 否 |
| 模型规模 | 8B | 2B/4B | 未公开 | 120B |
| 开源 | 未知 | 是 | 是 | 部分 |

**对你的研究**：HASE 是"修改者与执行者同一"这一 L3 特征**唯一出现在联合递归 setting 的工作**——同时触碰 L3（同一性）、L4（评估器可动）、L5（权重×harness）。概念上它是 12 篇里分级最高的候选，但也因此踩中最多的坑（信用分配、评估器腐败）。若开源，优先级提到最高；若闭源，只取"统一动作空间"概念。

## 9. 批判性问题清单

1. 评估组件编辑有没有更高层授权/冻结机制？模型被观察到"改宽评估器"吗？
2. harness 编辑动作的延迟收益怎么进 RL 优势函数？有无专门的信用分配设计？
3. 8B 匹配 120B 组合——训练成本、推理成本、基线复现方式三项是否对齐？
4. 统一动作空间里模型学到的 meta-策略长什么样？（改 harness 的频率/时机分布——这是最有价值的分析，比成功率更有信息）
5. 开源吗？三个任务的 harness diff 会发布吗？
