## 1. 动机（漏斗）

1. **领域现状**：长程 agent 改进有两条路——冻结模型改 harness，或训权重；联合工作（WHALE/SIA/Co-Harness）都默认"两个都要"，但**选择依据从未被形式化**。
2. **现有痛点**：(1) 无诊断的联合优化无法回答"这次增益该归谁"；(2) 训进权重的增益是否可移除 harness 而保留，从未被检验（removability 问题）。
3. **核心矛盾**：两种杠杆修的失败类型不同，但现有协议把失败当标量（分数不涨），不看失败是什么。
4. **本文目标**：给出可操作的 diagnose-then-intervene 规则，连用两次——选杠杆一次，选内化内容一次。
5. **切入角度**：失败构成（failure composition）作为可观测的诊断量。
6. **核心 idea**：按"第一个触发的信号"给失败轨迹打标签——process failure（调用被阻/循环/步数耗尽）由 harness 修，其行为可训进权重；content failure（交付了计划但计划差）只有权重能修。

**判断**：真问题，且是 WHALE 调度问题的互补层——WHALE 问"何时切换"（调度层），本文问"凭什么诊断该切换"（失败构成层）。

## 2. Insight 与理论依据

- **核心 insight**：失败不是标量而是分布；分布的构成（process vs content）直接可读、且与正确杠杆一一对应。
- **理论依据**：无形式理论；方法论贡献。
- **严格使用还是隐喻借用**：N/A。
- **逻辑跳跃**：二分法的完备性（是否所有失败都能归入两类）依赖"first signal that fires"的标注协议——标注可靠性本身是隐含假设。

## 3. 方法（摘要级重构）

### 3.1 协议骨架

1. 让 harness 自进化循环先把系统改强（DeepPlanning：Qwen3.5-4B held-out 0.16→0.30，9B 0.32→0.44）；
2. **失败构成标注**：按 first-signal 分离 process/content 失败（4B：交付率 55%→90%，content failure 留给权重）；
3. **交叉分解**：seed/进化 harness × 基础/训练权重的四格设计，读出走哪些增益可内化；
4. **LoRA 内化检验**：进化 harness 轨迹上训 adapter——原 harness 下两个尺寸均 +0.13；4B 上 adapter 与 harness 叠加使 held-out 分数翻倍以上；9B 上 **adapter 单独追平整个进化线**，content failure 从 1/4 降至 1/20；
5. **placebo 对照**：答案打乱轨迹训出的 adapter **低于基模型**——排除"任何额外训练都有益"。

### 3.2 关键设计（三段式）

> **placebo adapter**
> - 功能：排除"只是多训练了"的零假设
> - 核心思路：轨迹结构保留、答案打乱——训练量相同、信号无效
> - 设计动机：self-distillation 类结果的常见混淆就是"训练本身"；这是本系列笔记中首次见到的安慰剂对照，应成为标准件

> **same-night 新鲜锚点评估**
> - 功能：控制闭源 API/环境漂移
> - 核心思路：所有分数为对 fresh anchors 的四次 rollout 均值，同夜完成（除标注外）
> - 设计动机：承认评估环境非平稳——与 RQGM 的"评估器漂移"问题在协议层的呼应

> **迁移检验（WebArena-Lite）**
> - 功能：测规则的跨域性
> - 核心思路：117 个未见任务 +0.09；增益存在于"模型看到什么"（harness 侧），adapter 无加成
> - 设计动机：证明 diagnose 规则的结论不是单域伪影——同时诚实呈现"该域增益不可内化"的负结果

## 4. 实验（摘要级）

- 基准：DeepPlanning + WebArena-Lite（迁移）；模型：6 家族 8 个模型；评估：4-rollout 均值、fresh anchors、same-night。
- 缺口（未见全文）：失败标注的 inter-rater 可靠性、DeepPlanning 的 held-out 构造、9B adapter 追平进化线后"harness 是否仍然必要"的部署分析。

## 5. 评估三问

- **Q1 内部判据**：被分析循环的门控未见详述；本文的贡献恰在于给这种循环外加诊断层。
- **Q2 外部审计**：placebo 对照 + fresh anchors + 跨 8 模型 2 基准——审计意识强于本簇平均。
- **Q3 量化方式**：失败构成的比例化报告（content failure 1/4→1/20）是本簇罕见的可归因量化。

## 6–7. 结论与缺点

- 结论站得住的部分：失败构成可诊断杠杆选择；内化增益可用交叉分解测量；placebo 为必要对照。
- **额外缺点**：二分法在失败多因果交织时（process 与 content 同轨迹）的标注规则未见；"first signal"协议对长轨迹可能把根因误标为早发症状；9B 上 adapter 追平进化线部分削弱了"联合必要"的叙事——**单杠杆足够时联合的价值是什么**，需逐域回答。
- **最可能被攻击的点**：二分法的完备性与标注可靠性。

## 8. 谱系定位

- **前置**：被分析对象是 Self-Harness 式自进化循环；方法论上承接 RRSI/DemoEvolve 的失败审计传统。
- **定位一句话**：L5 簇的第一篇"实验方法论文"——不提供新系统，提供让双循环结论可信的诊断与对照工具。
- vs 对比：**vs WHALE**：WHALE 用调度扫描找切换点（行为层），本文用失败构成读切换点（诊断层）——两者组合才是完整的切换理论；**vs SIA**：SIA 让 LLM 凭轨迹直觉选杠杆，本文给出可复现的标注协议——同问题的启发式 vs 程序化解法。

## 9. 批判性问题清单（供组会讨论）

1. （方法）process/content 二分法在同轨迹多失败时的标注规则是什么？first-signal 协议的 inter-rater 一致性多少？
2. （实验）9B 上 adapter 单独追平进化线——此情形下 harness 的剩余价值是什么？联合优化是否在部分域只是"更贵的权重训练"？
3. （实验）WebArena-Lite 上增益不可内化（"增益在模型看到什么里"）——这是否证伪了"diagnose 规则可泛化"的强版本？哪些域特征预测可内化性？
4. （协议）same-night fresh anchors 控制评估漂移——该协议对 harness 进化循环内部的纵向比较是否也应强制？循环内跨夜评估是否存在隐性漂移？
5. （整体）若失败构成随迭代演化（harness 修完 process 后 content 占比上升），diagnose 规则需要多频繁地重新运行？规则本身有无稳定性分析？
