## 1. 研究背景与动机

**领域位置**：智能体基础设施。2026 年的智能体生态已被通信协议标准化（A2A 智能体间通信、MCP 工具接入），但**自我进化没有协议**——各系统的自我更新方式是临时的、异质的。

**核心问题**（摘要开头）：LLM 智能体可以通过改 prompt、造工具、变更其他运行时资源来适应环境；**管理这些异质更新需要一个共享的生命周期**——识别改进目标、评估候选、保留被接受版本。这正是 AGP 要补的缺。

**动机定位**：AGP 明确以 **A2A / MCP 的补充者**自居——后两者标准化"智能体如何通信/用工具"，AGP 标准化"智能体如何进化"。

---

## 2. 核心 Insight 与理论依据

### 2.1 关键洞察

1. **解耦"什么可进化"与"更新如何被提出"**（decouple what evolves from how updates are proposed）——这是 AGP 的第一设计原则：资源注册与更新机制正交，任何资源类型都能接入同一更新生命周期。
2. **memory 升为第一类资源**：与 prompt、agent、tool、environment **并列**的第五种协议资源（这是文献中"记忆"地位的最高规格表述）。
3. **进化需要血缘与回滚**：版本化接口 + 可审计历史 + 已保留状态恢复——把自我进化从"改了就改了"变成**可治理**的过程。
4. **协议先行、系统随后**：先定义协议（AGP），再给演示系统（AGS）——论文的自我定位是基础设施提案而非单一方法。

### 2.2 理论依据与方法论谱系

- **无学习理论**；方法论来自**分布式系统与协议设计**（版本化资源、生命周期状态机、审计日志），是 REST/CRDT/包管理思想向智能体进化问题的迁移。
- 在 RSI 谱系中的位置：不提供新的"改进算法"，而是给所有改进算法提供**统一的承载平面**——任何 proposer 都能接入 SEPL。

### 2.3 与已有工作的联系

- **vs A2A / MCP**：互补而非竞争（论文自述）；
- **vs 单一资源的自进化工作**（prompt 优化、技能库、记忆管理）：AGP 把它们统一为"五类资源的同一生命周期"；
- **vs MOSS / Self‑Harness**：那些是具体改进方法；AGP 是可以承载它们的协议层。

---

## 3. 方法详解

### 3.1 双层协议架构

**Resource Substrate Protocol Layer（RSPL，资源基底层）**：
- 将 **prompts、agents、tools、environments、memory** 表示为**协议注册资源**；
- 每个资源有**显式状态**与**版本化接口**；
- 资源的实例化、检索由协议统一管理。

**Self‑Evolution Protocol Layer（SEPL，自进化层）**：
- 定义**封闭循环操作接口**：候选提案（proposal）→ 评估（assessment）→ 提交（commit）；
- **可审计历史**（auditable histories）：每次变更留痕，支持血缘追踪；
- **状态恢复**：支持回滚到任何已保留的资源版本。

### 3.2 演示系统 AGS（Autogenesis System）

- 一个**自进化多智能体系统**：在执行期间动态**检索、实例化、精炼**资源；
- 展示五类资源**共享同一更新生命周期**的执行案例。

### 3.3 可修改范围（RSI 视角）

| 层级 | 本文触及？ | 说明 |
|---|---|---|
| 提示词 | ✅ | 协议资源之一 |
| 智能体定义 | ✅ | "agent" 本身是协议资源——结构上最"自我"的一点 |
| 工具 | ✅ | 协议资源 |
| 环境配置 | ✅ | 协议资源 |
| **记忆** | ✅ | 第一类资源——本文标志性强调 |
| 权重 | ❌ | 未涉及 |
| 协议自身（RSPL/SEPL 规则） | ❌ | 固定——协议的稳定性正是其价值 |

### 3.4 RSI 实现程度

- **改进闭环**：存在且被**协议化**——提案/评估/提交是显式接口而非隐含流程；
- **改进器自身会被改进吗**：不会——协议层固定；但"agent 定义"作为资源意味着**执行体**可被改写；
- **分级判定**：**L1.5–L2**。理由：改进范围覆盖五类运行时资源（比纯记忆/技能的 L1 宽），且 agent 自身在资源列表中（触及 L2 的"自我"性）；但改进机制（SEPL 循环）不可改写，亦无证据表明提案者与被改者构成递归。它是"自我进化的**基础设施**"而非"自我进化算法"——分级的对象是 AGS 演示系统而非协议本身。

## 5. 评估和测评依据（评估三问）

### Q1 内部判据：怎么判断"更新成立"？

- **判断主体**：SEPL 的 **assessment（评估）环节**——协议规定提案须经评估才能提交；但**评估的具体判据由实现者填充**——协议只规定"必须有这一步"，不规定"用什么标准"。
- **性质**：**协议化的门控**——门控的位置被标准化，门控的判据被留白。这既是灵活性（任何评估器可接入），也是本文作为"协议论文"的固有边界。
- **审计内置**：auditable history + 状态恢复使"判断可追溯"成为协议级保证。

### Q2 外部审计：怎么判断系统确实在改进？

- **对照设计**：非进化配置作为基线；
- **成本透明**：token 成本随性能一并报告——"改进的代价"进入审计视野；
- **缺口**（摘要级）：无 held‑out 设计、无多轮进化轨迹、无与其他自进化方法的横向对比（AGS 的对照只是"不进化"）。

### Q3 量化方式：如何度量改动？

- **改动即版本**：每次 commit 产生新版本，血缘链完整——改动编目是协议级原生能力（这是 AGP 相对所有"改代码"工作的独特优势：DGM/SICA 的改动编目是事后整理，AGP 的是协议强制）；
- 性能与成本双指标。

**评估三问总评**：AGP 把"评估三问"从**方法属性**变成了**协议要求**——任何接入 SEPL 的改进算法都被强制留下提案、评估、提交的痕迹。它不回答"什么判据好"，但保证"判据存在且可审计"。

## 6. 实验结果与分析

- **主结果**（摘要级）：三类基准超过非进化配置；五类资源统一生命周期被实际演示。
- **诚实之处**：把 output‑token 成本列为报告项——承认自我进化不是免费的。
- **缺口**：摘要未提供效应量、方差、任务数；对照仅为"不进化"，未与任何主动改进方法对比——**协议的价值目前主要靠演示而非竞争性证据**。

---

## 7. 结论与意义

- **结论**：自我进化可以被协议化；五类异质资源能共享统一的生命周期、审计与回滚。
- **领域意义**：
  - 在 2026 年"harness/进化方法大爆发"的背景下，AGP 是罕见的**向后兼容的基础设施提案**——它不发明新的改进算法，而是给所有算法一个共同的家；
  - "memory 作为第一类资源"呼应了同期记忆研究的地位上升；
  - 若被采纳，将成为 RSI 系统的"审计合规层"——对安全治理有直接价值。
- **局限**：
  1. 协议价值依赖生态采纳，单点演示不能证明通用性；
  2. 评估判据留白——"协议强制有门，不保证门有效"；
  3. 竞争性证据弱（只对比非进化基线）；
  4. 多智能体场景下的并发更新冲突（两个 agent 同时改同一资源）未见处理方案（所读材料）。

## 9. 批判性问题清单（精读者视角）

1. **协议过早标准化的风险**：领域尚未收敛（改进算法每月翻新），此时冻结接口会不会像早期 web 协议一样很快过时？v1→v6 的大幅改写本身就暗示接口尚不稳定。
2. **"评估环节留白"是否把最难的问题推给了实现者**？自我改进的核心难题恰恰是"用什么判据"——AGP 标准化了容易的部分（生命周期），绕开了难的部分（判据设计）。
3. **血缘审计的开销**：全量版本化 + 审计历史在长程运行中的存储与检索成本未量化。
4. **演示系统的说服力**：AGS 只证明"协议能跑"，未证明"协议有用"——需要一个"没有 AGP 就做不成"的案例。
5. **资源粒度的本体论问题**：prompt/agent/tool/environment/memory 五分类是否完备？harness、训练数据、评估器置于何处？——修改范围层级表中后三者在 AGP 本体里缺席。
