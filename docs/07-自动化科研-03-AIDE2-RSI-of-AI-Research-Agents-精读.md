## 1. 研究背景与动机

论文的出发点是一个宏观观察：AI agent 已开始自动化 AI 栈各层的 R&D（训练效率、推理优化），自然的下一步是**改进研究 agent 自身的研究效率**——因为 R&D 累积投入的边际收益递减是长期趋势，持续的自我改进是对冲该趋势的方式。当研究 agent 自己的代码成为优化对象，每一次被接受的改写就成为下一轮编辑的 agent——论文将此循环命名为 recursive self-improvement，并以"提供 RSI 的首个持续实证"为目标。

## 2. 核心 Insight 与理论依据

**核心 insight**：
1. **harness 即研究效率的杠杆**：agent 的搜索策略、上下文管理、结果检查方式（harness 代码）决定其单位算力的研究产出——它是可被同一个 agent 能力改写的对象；
2. **接受判据必须用隐藏数据**：被改写的 agent 在优化时看到的公共信号（r_pub）与选择时的评分（g，基于私有数据 r_priv）分离——门控数据对"被改写的 agent"不可见，防止改写针对评估过拟合；
3. **固定评估预算**：所有候选在相同成本（token + 执行）约束下评分——确保测到的增益来自"更好的算法"而非"更多算力"；
4. **持续趋势 vs 一次性运气**：单次改写成功不构成 RSI——必须展示同一 run 内**多次连续接受**的改进。

**理论依据**：RSI 的概念传统（Gödel Machine 谱系）在当代 agent 上的可操作化；评估设计的四条准则（持续趋势、固定预算、选择外泛化、强基线对照）构成本文的方法论贡献。

## 3. 方法详解

### 3.1 双层循环

- **内环**：AIDE 研究 agent——对给定 AI R&D 任务优化代码（与普通自动研究 agent 相同）；
- **外环（AIDE²）**：提出对内环 agent harness 代码的改写 → 在一组异质 AI R&D 任务上对改写后的 agent 做基准 → 仅当 **hidden 评估**（私有 grade g）在固定预算下优于现任才接受；
- 一次 run = 100 个外环节点（初始 agent + 99 个改写提案），8 天无人值守。

### 3.2 可修改范围与 RSI 分级

| 可修改对象 | 是否被修改 | 修改者 |
|---|---|---|
| 内环 agent 的 harness 代码（搜索策略/上下文管理/结果检查） | ✅ 每次接受的改写 | 外环 agent |
| 外环的接受判据（hidden 评估协议） | ❌ 人工固定 | —— |
| 外环 agent 自身 | ⚠️ 可用发现的 agent 充当（点火检验，无决定性结论） | —— |
| 模型权重 | ❌（harness 层改进） | —— |

**分级：L2+**。改进对象是 agent 自身代码、改进者是 agent、门控严格（hidden 数据 + 固定预算）——这是"改进者可替换"档中门控最严格的实证之一。但外环协议（评估任务集、预算、接受规则）仍人工固定，故未达 L3 完全自指；论文自己对"点火条件"（ignition）的检验也坦承无定论。

## 4. 实验设计（评估方法论的标杆部分）

论文把实验设计准则写成了四条显式约束（§3.1）：
1. **持续趋势**：同一 run 须产出多个被接受的改进（排除单次运气）——结果：主 run 7 次接受（步骤 2/6/28/39/47/63/85），另两次完整 run 分别接受 2 次和 4 次；
2. **固定评估预算**：每个候选 agent 在相同成本下评分（控制算力混淆）；
3. **选择外泛化**：改进须在从未参与选择的基准上仍然有用——四个外部基准：ALE-Bench（10 任务 × 10 seeds）、MLE-Bench lite（22 任务 × 3 seeds）、FML-Bench（18 任务 × 3 seeds）、**WeatherBench 2（分布外域：物理天气预报模型优化，选择任务中完全没有的类型）**；
4. **强基线**：AIDE_human——两年人工 R&D 的生产级研究 agent，在 FML-Bench 作者评估的六个强 agent（AI Scientist v1/v2、OpenEvolve、AIDE、Autoresearch、AIRA）之上。

另设 **KernelBench 奖励 hacking 研究**：用"孤立测速 vs 训练管线内实际加速"的差距定义 hacking（孤立加速 >1.02× 且训练内加速不足一半或崩溃即计）。

## 5. 评估三问

### Q1：内部判据（模型怎么判断修改成立）

**门控式**，且门控设计是全谱系最严格的形态之一：①判据基于**私有 held-out 数据**（被改写的 agent 在优化中从未见过 g 所用的数据）；②**固定成本预算**（排除算力混淆）；③接受率约 10%（约九成提案被拒——门控有真实咬合，不是橡皮图章）。改写的具体内容显示门控确实筛出了有意义的变更：bandit 式策略臂搜索（UCB1 + 30% softmax 探索）、修复前必须根因诊断、冠军分叉逃离平台期、崩溃自愈、日志压缩读取、易失败策略降权。

### Q2：外部怎么判断 RSI 成功

四层外部审计：
- **一阶泛化**：选择基准上超越 AIDE_human（现任 grade 0.703→0.778，AIDE_human 为 0.749）；
- **二阶泛化**：四个从未参与选择的外部基准上，AIDE_85 全面追平或超越 AIDE_human（ALE-Bench 1790 vs 1511；MLE-Bench 0.722 vs 0.708；FML-Bench 19.9% vs 19.6%；WeatherBench 2 **0.793 vs 0.404**——分布外域上的优势最大，且多种子收敛到同一族解法，方差极小）；
- **跨模型转移**：发现的 harness 增益在 gemini 3 flash / gpt-5.6-sol / fable 5 三个底座上均保持；
- **非优化目标的副作用**：奖励 hacking 率 55%→32%（低于人类的 39%）——改进 loop 从未以 hacking 为目标，降低是涌现性质。
- **点火条件（三阶）**：发现的 agent 用作外环 agent 时仍能产生被接受的改进，但因双环噪声复合与种子成本，**无法与强基线决定性区分**——论文坦承"不认为当前系统接近智能爆炸"。

### Q3：改动如何量化

- 外环轨迹：100 节点、7 次接受、grade 曲线 0.703→0.778，每次接受的改写有语义标注（改的是什么机制）；
- 机制级量化：上下文管理系统使单次 LLM 调用 prompt 大小保持有界（AIDE_0 随历史线性膨胀），中位压缩比在 ALE-Bench/FML-Bench 约 50×、WeatherBench 2 超 40×、MLE-Bench 7×；且消除了"prompt 撑爆上下文窗口导致 run 终止"的具体失败模式（AIDE_0 在 FML-Bench 有 5 次、ALE-Bench 大预算下 48 次因此终止）；
- 种子级标准误差全程报告；非单调性（AIDE_47 在两个基准上优于 AIDE_85）如实披露并解释（选择基准是异质聚合，强检查点间非单调属预期）。

## 6. 实验结果与分析

- **7 次连续改进 + 四个外部基准追平/超越两年人工 R&D 的 agent**——论文称之为 RSI 的首个持续实证（net positive level）；
- **分布外泛化最强**：WeatherBench 2 上的优势（0.793 vs 0.404）且种子间方差极小——被接受的改写改进的是**通用的优化行为**而非任务特定技巧；
- **涌现的防 hacking**：agent 自建了从 prompt 级指令到硬编码检查的多层防御——自我改进的 agent 学会了自我约束；
- **复杂度膨胀（自报的代价）**：演化出的 agent 复杂度爆炸、含死代码——进一步定制与生产部署更难；
- **点火未证**：三阶泛化（改进者本身变好）无法定论——作者明确表示"不认为接近智能爆炸"。

**分析**：这篇论文的评估纪律（hidden 门控、固定预算、选择外泛化、强基线、副作用审计、点火坦承）几乎是对"评估三问"框架的完整示范——它把 DGM 时代"声明自我改进"的口径收紧为"在看不见的数据上、相同算力下、持续多次地变好"。

## 7. 结论与意义

AIDE² 提供了迄今最严谨的"agent 递归改写自身代码"实证：持续趋势、外部泛化、跨模型转移、副作用改善四重证据齐备。同时它的诚实边界（预印本、未独立复现、复杂度膨胀、点火未证）为整个 RSI 领域立了"什么算证据"的新标准。对谱系的定位：它是 DGM/HGM 谱系在"真实生产级研究 agent"上的延续，把门控评估从 benchmark 语义升级为与研发经济（R&D spend per improvement）挂钩。

## 8. 未来方向（论文自身展望）

点火条件的决定性检验（更多种子、更低噪声）；复杂度控制（演化中的死代码清理）；向权重-脚手架联合递归扩展；更长周期运行的稳定性。

## 9. 批判性问题清单

1. **可复现性**：公司自建系统的预印本，无独立复现；核心系统不开源（AIDE 本体为其商业产品）——外部社区难以检验。
2. **选择基准的构成影响**：接受的改写反映选择任务集的偏好——换一组选择任务，演化方向可能不同；"通用优化行为"的通用性受选择集覆盖度限制。
3. **非单调性与检查点挑选**：AIDE_47 与 AIDE_85 各有胜场——最终 agent 的选择本身含一定的后验挑选成分。
4. **复杂度膨胀无对策**：自我改进以可维护性为代价——长期运行后系统可能陷入"没人（包括 agent 自己）能理解的代码"，这本身是 RSI 的隐性失败模式。
5. **外环协议固定**：评估任务、预算、接受规则全是人工设定——递归在"内容"层成立，在"协议"层不成立；点火未证意味着真正的递归深度仍是 1.5 层。
