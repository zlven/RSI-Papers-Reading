## 1. 动机漏斗：六步走到问题

1. **大目标**：LLM 训练自动化。
2. **现状**：自主训练被框为 recipe 搜索（超参/配方空间）——训练 harness 基本静态。
3. **裂缝**：agentic RL 里这个局限被放大——**瓶颈随训练移动**（先后天不同），标量奖励**掩盖多样失败模式**（同一个低分可能是探索不足/信用错配/环境噪声）。静态 harness 读不出这些。
4. **问题**：训练 harness（解释 rollout 证据、产生训练干预的系统）本身能否成为进化对象？
5. **约束**：进化干预必须防止"无效高分分支被晋升"（诊断错误驱动的假阳性）。
6. **本文问题**：策略与训练侧 harness 的共进化框架，全流程由经验反馈驱动。

**定位独特性**：12 篇里唯一改进**训练侧** harness 的——WHALE/Co-Harness/HELIX 改的都是推理侧（部署时中介模型-环境交互的系统）；EvoTrainer 改的是训练时中介 rollout-学习信号的系统。

## 2. Insight 与理论依据

### 核心 Insight

"训练 harness"概念本身即贡献：把诊断器、干预生成、干预验证、技能库这些训练辅助系统**显式对象化**，于是它们可被进化。recipe 搜索的天花板来自它假设"评估 recipe 的系统"是完美的——EvoTrainer 指出这个假设在 agentic RL 失效：标量奖励 → 失败模式不可分 → 诊断必须自己进化。

四步循环的诊断-干预结构（诊断 rollout 证据 → 修订诊断 → 回测干预 → 积累技能）与科学方法同构，且**干预要回测**——这是 harness 进化文献里罕见的防假阳性门（对照 DGM 的准入只要"能编译+保持编辑能力"）。

## 3. 方法拆解（摘要可推断部分）

### 整体骨架

```
循环：
  1. 诊断：rollout 级证据分析（失败模式归因）
  2. 修订诊断：诊断器本身是进化对象
  3. 干预回测：训练干预先在历史证据上回测再启用
  4. 技能积累：有效干预→可复用技能库，塑造后续搜索
策略与训练 harness 共进化
```

### 关键设计

**设计 1：rollout 级诊断（对标量奖励的解掩蔽）**
- 功能：从轨迹细节提取失败模式，而非只看标量回报。
- 设计动机：标量奖励的信息瓶颈是 agentic RL 自动化的第一障碍。

**设计 2：进化诊断 + 干预回测（防腐败双机制）**
- 功能：摘要明确"进化诊断**防止无效高分分支被晋升**"——诊断器质量门控干预准入。
- 设计动机：自主训练的最大风险是自骗（钻奖励空子的分支被当成进步）；回测 = 用历史证据当干预的 hold-out。

**设计 3：可复用技能积累**
- 功能：有效干预沉淀为技能，"塑造后续搜索"——搜索空间随历史收缩/定向。
- 与 SKILL0 的对照：SKILL0 内化技能到权重，EvoTrainer 沉淀技能到**训练 harness 的技能库**（外挂但作用于训练侧）。

## 4. 实验声称（摘要，未核）

- 三域：数学推理、竞赛编程、**仓库级 SWE**；
- 结论：同数据、同代码库、同评估协议下**匹配或超过人工工程 RL 参考**，长程 agentic SWE 增益最大；
- 轨迹分析三发现：保留策略**跨域发散**（没有普世最优训练策略——与 WHALE 的 regime 依赖互证）；进化诊断防假阳性晋升；技能库塑造后续搜索。

**严谨性评价（摘要级）**："同数据/同代码库/同协议"的对照声明是 12 篇里最规范的实验纪律表述之一（点名三个混淆源并逐一控制）。但"人工工程 RL 参考"的强度（哪个 baseline？谁调的？）待核。

## 5. 评估三问

**Q1 内部标准**：rollout 诊断 + 干预回测——内部标准有**历史证据校验**这一层，比普通"验证集分数"门严格。
**Q2 外部审计**：三同对照（数据/代码库/协议）是直接回答外部审计的设计；开源状态摘要未声明（4.3MB PDF 暗示实验量大，若不开源复现门槛高）。
**Q3 量化**：跨域发散的定性发现有价值；成本核算未见。

## 6. Contribution 提炼

1. **训练侧 harness 的对象化**：把 harness engineering 的作用域从推理侧扩展到训练侧——概念增量明确。
2. **诊断作为进化对象**：失败模式归因器自身可进化，且承担防假阳性门职能。
3. **干预回测纪律**：自主训练系统的防自骗机制设计（与 RQGM 的锚门、AIDE² 的隐藏评估同属"防腐败"家族，但作用于训练干预而非自修改）。
4. **三同对照实验纪律**。

## 7. 缺点与攻击面

1. **诊断进化的元问题**：诊断器由什么评估？"诊断的诊断"是否递归上升？摘要未提——若诊断器最终由人工校验，自主性声称要打折。
2. **回测的有效性边界**：历史证据回测防得住"过去的假阳性"，防不住分布漂移后的新型钻空子。
3. **技能库污染**：积累的"可复用技能"若含早期错误诊断的产物，会塑造后续搜索走向歧途（与 HELIX 的证据层对照：EvoTrainer 是否有来源链机制待核）。
4. **开源未声明**：复现性未知。

## 8. 谱系定位

**在 12 篇分类中**：E 类（训练侧）唯一篇，与推理侧八篇形成作用域互补。

| 维度 | EvoTrainer | WHALE/Co-Harness（推理侧代表） |
|---|---|---|
| harness 作用域 | **训练时**（rollout→学习信号） | 推理时（模型→环境） |
| 改进对象 | 诊断/干预/技能库 | prompt/工具/控制流/权重 |
| 防腐败机制 | 诊断进化+回测 | 验证集/白盒组件 |
| 对照纪律 | 三同（数据/代码库/协议） | 组件消融 |

**对你的研究**：EvoTrainer 补上了"harness engineering"版图的空象限——**训练侧的改进者**。若你的 RSI 分级扩展到训练循环，EvoTrainer 是"训练自举"的现存最完整实例。它与 HarnessBandit（下篇，训练时 harness 调度）的区别：EvoTrainer **改**训练 harness，Bandit **选**推理 harness——一改变一调度。

## 9. 批判性问题清单

1. 诊断器的质量由谁终审？人工在环的程度？（自主性声称的边界）
2. 回测能捕捉多少比例的无效干预？有没有假阴性（有效干预被回测误杀）的统计？
3. 技能库的规模增长曲线：技能积累是单调受益还是后期噪声主导？
4. 三域保留策略发散——发散的轴是什么？（探索强度？信用窗口？）这个分析比"超过参考"更有科学价值。
5. 开源吗？4.3 MB 的实验资产发布多少？
